# Asana standard MCP adaptation, local Build

Owner Song Haoran; original task AH-20261117-asana-connector. Preserve the original PAT-based project/task scope. Do not silently replace it with the separate official hosted MCP product, which requires an MCP OAuth app. Instead, independently implement a small standard stdio MCP server on the host-provided Node22 runtime, calling the same documented Asana REST endpoints. No Python/pip, downloaded implementation, SDK bundle, new OAuth app, or copied provider prompts are needed. This is a team-authored adapter, not Asana's official hosted MCP.

Source review completed before the adapter implementation: official public API documentation https://developers.asana.com/reference/gettasksforproject and https://developers.asana.com/reference/createtask were inspected2026-11-19. Only endpoint contracts and the independently authored existing connector's business scope are used. No upstream code, documentation prose, prompts, artwork, fonts or data will be copied. Existing unmodified source/license history is preserved under history/1.0.0. No Asana brand artwork is bundled. Service-account permission and PAT use remain separate from software distribution rights.

Proposed1.1.0 keeps slug asana, Chinese display name Asana 任务连接器, the original owner/task and ASANA_PERSONAL_TOKEN field. Four bounded operations: authorization status, paginated tasks of a specified project, read a specified task, create a named task in a specified project. No update/delete, arbitrary URL/request tool, attachment or project creation. Credential provisioning uses the host's normal token form and resolver; no agent-side token-file reading or copying. Runtime destinations are fixed to app.asana.com/api/1.0, redirects denied, bounded response/timeouts and no automatic writes retries. Tool schemas, errors and guidance are Chinese; API identifiers and business content are preserved.

Implement and validate locally, freeze exact Chinese archives, exercise actual stock-host loading, auth/read/create/readback/errors and Chinese prompts, retain original images and obtain explicit exact-package user test completion before any delivery PR. Hub acceptance of the new standard-MCP form remains unproven until actual moderation.
