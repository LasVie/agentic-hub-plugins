# Jira Cloud 1.1.0 设计

沿用原 Task 与范围，由有限 Node CLI 调用固定 MIT mcp-remote 内部客户端导出，连接官方 Atlassian MCP v2，保留原有 Jira 图标。认证及协议复用标准客户端，跳转适配保留其待处理 state、注册预检和重试保护，将官方 URL 交给宿主卡片。显式固定 Jira 读、搜、写，以及服务要求的基本账号 read:me/read:account 与离线刷新 scopes；发现扩大请求或令牌 scope 时失败，不默许加入其他产品。

每次业务调用建立短时 MCP 会话，分页发现并筛选 Jira 工具，读取当前可访问站点，核对 cloudId，再执行明确白名单中的命令。输入为 JSON 文件，写入字段限项目、类型、标题和描述；不开放已有事项编辑/删除/评论/分配及任意 execute 工具。写入结果不明时先查重回读，不能自动重试。子进程有总体超时、信号转发和最终强制清理，不依赖宿主 stdio 服务缓存。

依赖、账号、网络、授权取消和操作系统边界在中文 README 中明示。真实正常 OAuth、工具定义及业务结果仍须以当前精确制品在 stock 0.2.8 的实测为准。

本机引导先就绪，30 分钟登录等待有界；worker 在父 IPC 断开时退出，回调端口按配置目录稳定区分。实际 v2 站点封装按 data.resources/cloudId 解析并仅选 Jira 产品，创建参数使用真实 schema 的 issueType；未知范围外必填字段导致明确停止。当前精确包已完成卡片和聊天测试，证据及接口省略字段的限制见 TEST_REPORT.md。
