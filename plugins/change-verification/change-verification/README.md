# 变更影响与回归检查台 1.0.0

从本地 Git 两个提交的变更出发，整理直接修改和静态反向依赖候选，形成中文人工回归清单。你在浏览器面板填写实际结果、备注和截图，再交给 WorkSwarm 汇总、导出。

## 安装与第一次使用

1. 在 WorkSwarm 的**扩展 → 我的扩展 → 插件**中导入本地测试 ZIP。
2. 新建对话，选中**变更影响与回归检查台**。不要只把 ZIP 当聊天附件。
3. 输入：`用虚构演示仓库展示变更影响与人工回归面板，不要替我填写通过。`
4. 助手会调用工具创建包含两个真实提交的独立演示仓库，分析后打开面板。人工验证后选择结果、填写备注、按需添加截图，并点击**保存本项结果**。失败与跳过必须有备注；每项最多 3 张 PNG/JPEG，每张 1 MiB。
5. 回到同一对话说明已保存，请助手查询实际报告并导出。或直接在面板下载内嵌截图的完整 HTML 报告。

macOS 优先使用 WorkSwarm 自带 Node；需要 Python 3.9+、Node 20+ 和本地 Git。插件没有运行时 npm/pip 依赖，无需 Conda，也无需手动执行初始化命令。Linux 需要 PATH 中已有的 Node 与 Git，以及可访问本地链接的浏览器。Windows 未验证，当前包不声明支持。

## 分析真实项目

明确告诉助手本地 Git 仓库顶层绝对路径、基线和目标引用。例如：`我授权只读分析 /我的项目 的 release-baseline 与 HEAD，扩散深度 2，打开回归面板；不要执行项目代码或标记通过。` 引用必须已在本地，不会自动 fetch。

两个提交按端点比较；重命名按删除与新增列出。分别检查两份提交快照，保留删除文件的旧依赖链。变更项与间接依赖分别显示，每项带文件路径、证据、风险启发式和建议步骤。工具返回受支持文本的提交差异片段，助手可据此完善尚未录入结果的条目步骤。可通过 `modules` 参数将文件或目录前缀对应到准确的中文业务名称。

这不是测试执行器。清单初始全部为未验证，用户在面板录入结果；静态候选可能误报或漏报，不证明功能已经通过、没有缺陷或完整覆盖。没有变化也不等于验收通过。虚构演示项目不应作为真实业务测试。

## 报告与历史

状态目录：`~/.cache/agentic-hub-change-verification/`。`reports/` 保存实际清单与用户录入的证据，`demos/` 保存独立演示仓库，`exports/` 保存按修订冻结的报告。

- HTML：内嵌截图，单文件离线查看。
- Markdown：中文清单、实际状态、备注和证据 SHA-256。
- CSV：便于表格交接，保留未验证、失败和跳过。
- JSON：结构化结果，含截图原始编码及字节哈希。

新对话可用 `verification_status()` 列现有报告，再打开同一报告；不会自动清理或重置历史。报告修订号阻止旧面板覆盖新结果。若提示修订过期，先刷新，再保存需要的更改。每次只编辑并保存一项；刷新或保存后页面会重新读取已保存状态。结束 WorkSwarm 连接后旧面板链接会失效，需要在新对话重新打开。

## 范围、限制与错误

只读已授权仓库的 Git 对象；不运行项目代码、不拉取远程、不修改仓库/全局配置、不自动开放 Git 安全目录。仅在自己的缓存保存报告。面板绑定 127.0.0.1，并检查访问令牌和来源；不要分享包含令牌的链接。

索引支持常见 TS/JS、Vue、CSS/HTML、Java/Kotlin、Swift/ObjC、Dart 静态引用；不等于完整语言解析。隐藏/敏感路径、构建产物、依赖、符号链接、二进制和非 UTF-8 内容会跳过。每快照最多 5000 路径、1500 个文本索引文件、单文件 256 KiB、总文本 16 MiB。超过 100 个变更文件或受支持文本差异输出超过 1 MiB 会拒绝；差异片段最多 40000 字符，清单最多 200 项，截断时提示。扫描结果和跳过原因一并保留。

不包含原版 DSH 注入、远程仓库凭据、设计平台、崩溃服务或外部缺陷提交。启动失败时保留实际错误；不要修改宿主校验器、注册表、安全设置或全局环境来绕过。
