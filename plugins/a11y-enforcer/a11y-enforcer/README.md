# 网页无障碍检查

检查网页界面代码有没有无障碍问题（对照 WCAG 2.2 AA）：哪张图没有替代文字，哪个按钮读屏软件读不出名字，哪个输入框没有标签，哪个 `div` 只能用鼠标点，文字和背景的颜色对比度够不够。每条问题带文件、行号和 WCAG 成功标准编号，并说明怎么改。

一个技能加两个只读的原生工具：

| 名称 | 类型 | 用途 |
| --- | --- | --- |
| `web-accessibility-check` | 技能 | 指导先扫描、再算对比度、再读代码补查扫描看不到的键盘、焦点、动态更新、目标尺寸和动效，最后按“阻断、错误、警告”写出中文检查报告 |
| `a11y_scan` | 原生工具 | 静态扫描 `.html`、`.htm`、`.jsx`、`.tsx`、`.vue`、`.svelte`、`.astro` 文件或文件夹，列出 20 类标记层面的问题 |
| `a11y_contrast` | 原生工具 | 计算文字色和背景色的 WCAG 对比度，判断 AA（正文 4.5:1、大字 3:1）、AAA（正文 7:1、大字 4.5:1）和界面组件（3:1）是否达标 |

## 使用示例

- “帮我检查一下这个前端项目的界面代码有没有无障碍问题，按严重程度列出来。”（先给出项目目录的本机路径）
- “文字颜色 #777777、背景白色，对比度够不够 WCAG AA？”
- “这个登录表单读屏软件和键盘能正常用吗？帮我看看哪里要改。”

回答默认使用简体中文；你明确要求其他语言时按你的要求。

## 能查什么

- **图片、按钮、链接、表单**：没有 `alt` 的图片，没有文字或名称的按钮和链接，没有标签的输入框、下拉框和文本域，意思不明的链接文字（“点击这里”“更多”）。
- **键盘**：带点击事件却没有 role、tabindex 和键盘事件的 `div`、`span`，没有 `href` 当按钮用的 `<a>`，正数 tabindex，`role="button"` 等没有 tabindex。
- **页面设置**：缺少 `lang`，viewport 禁止缩放，iframe 没有 title，带声音的自动播放，没有字幕轨的视频，标题层级跳级，去掉焦点轮廓。
- **颜色对比度**：支持 `#rgb`、`#rrggbb`、`#rrggbbaa`、`rgb()`、`rgba()` 和 20 个基本英文颜色名；带透明度的前景色按背景色混合后计算。

规则一览见 `skills/web-accessibility-check/references/rules.md`。

## 它做什么，不做什么

- 两个工具只读你指定的文件，不改文件、不写文件、不联网、不保存任何内容，不需要账号。
- 静态扫描只看标记里直接写出来的内容：看不到运行时生成的文字、传给自定义组件的属性和样式表里的 CSS；对比度工具不会自己去读主题文件，颜色要先从代码里找出来，叠在图片或渐变上的文字它算不了。
- **没有发现问题不等于符合 WCAG。** 目标尺寸、焦点管理、动态更新、动效，以及用键盘和读屏软件（VoiceOver、NVDA、讲述人）的真实体验，需要读代码补查或人工验证；这个插件也不能替代正式的无障碍审计。
- 安全上限：单个文件不超过 1 MB；每个文件 10 秒、一次调用 60 秒的时间预算；一次调用最多 3000 个文件、总计 200 MB；一次最多给 10 个路径。超出上限的文件会被跳过，并在结果里说明，不会假装扫过。文件夹里会跳过 `node_modules`、`dist`、`build` 等目录和符号链接。
- 文件按 UTF-8 读取；其他编码的文件里的中文会变成乱码，但标签结构仍能识别。
- 只有你要求修复时，技能才会改代码，并且改动尽量小、改前说明。
