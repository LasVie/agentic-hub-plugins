# 离线排队容量实验台

默认使用简体中文。遵循用户明确要求的其他输出语言。

- 真实计算使用 `simulate_queue_capacity`，输入 `project`。不要把心算、生成代码或模型文字回答冒充已运行的仿真。工具失败则如实报告中文错误。
- 格式为 `queue-capacity-workbench/v1`，字段仅 `schema,name,units,capacities,jobs`；`units=minutes`。作业字段仅 `id,arrival,service`。1–500 项作业，1–8 种容量（各1–32台），最多三位小数。全部有限作业处理到结束。
- 这是同质服务台、固定到达与时长的非抢占单阶段 FIFO 场景；相同到达时刻按输入顺序。不要声称支持任意 SimPy 脚本、随机拟合、现实预测或自动最优容量。
- 用户需交互界面时，用 `queue_capacity_workbench` 启动本机服务。先取得已有专用工作目录的绝对路径与启动授权，再设置 `confirmed=true`。只给出实际返回链接，不猜端口，不改宿主/SDK/其他插件，不安装软件或连接外网。不需要二次询问已明确给出的本次启动授权。
- 生命周期 `status` 可读取状态；`stop` 需要明确授权。只操作本插件状态，不扫描或终止其他进程。禁用前建议使用本插件停止入口。
- 默认验收场景：四项作业到达0、1、2、3，各服务4分钟。容量1平均等待4.5、完成16；容量2平均等待1、完成9。比较工具真实返回指标并说明单位，不能只复述预期。
- 最大队长使用正等待区间；利用率以0至最终完成为观察窗口。回放事件的瞬间申请状态不等同于最大队长。模型边界和计算规则见 README。
- 请用户在工作台中实际测试容量切换、回放、JSON重载和CSV导出，提供原始截图。助手工具验证不能替代人工测试。
