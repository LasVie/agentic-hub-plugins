# {{CHANNEL_NAME}} 运营规范

这是 AI 助手每天开始制作前最先阅读的作业指令。
结果不满意时，修改的是本文件里的句子，而不是代码。

## 开工前检查

1. 读取 `channel.json`、`state.json` 和今天的 `runs/YYYY-MM-DD/`（可调用 `video_channel status`）。
2. 今天的栏位（长视频 / 短视频）若已有已发布或已预约的视频 ID，**不再新建，直接结束。**
3. `production/jobs.json` 中记录有进行中的生成任务时，不要重新提交，继续用同一 job ID 取回结果。

## 每日制作 7 步

1. **调研**：寻找今天的选题候选，把来源 URL 和核实时间写入 `runs/YYYY-MM-DD/sources.json`。
2. **脚本**：长视频与短视频脚本分开写。短视频前 3 秒以问题或具体画面开场。
   遵守 `channel.json` 中的禁用表达和事实规则。
3. **配音**：用 `channel.json` 的 voice_id 生成旁白。**提交请求后立即把 job ID 记入 `production/jobs.json`。**
4. **画面**：制作场景图片 / 片段。不使用无授权的照片或电视片段，来源记入 `rights.json`。
5. **渲染**：用 `scenes.json`（场景图片与时长）+ 旁白生成 MP4。
   可调用 `video_channel render`（运行目录如 `runs/YYYY-MM-DD/short`）。
6. **字幕与检查**：按实际旁白校准字幕时间，并通过 `video_channel preflight` 机器检查。
7. **上传**：仅当 `authorization.daily_upload` 为 true 时才预约上传。核对标题、说明和 AI 合成内容披露项。
   **只有在平台后台亲眼确认预约状态和视频 ID 后才记为完成。**

## 必须遵守的规则（来自真实事故）

- 同一天不重复生成、上传同一个视频。
- 没有旁白的样片、音频为空的文件不发布。
- 短视频字幕放在不会被手机底部界面遮挡的位置。
- 不做额外付费、充值或订阅变更；需要时把金额和理由交给人来决定。
- 指标在发布后 24 小时、72 小时、7 天分别记录；处理中的数值不要填 0。
- 短视频与长视频指标不混在一起比较；样本少于 3 条不下结论。
