# 文档数字核对

核对一份文档里的数字对不对得上：哪个合计比分项多了 200，哪个百分比和个数对不上，哪个日期的星期写错了，哪个公式少算了一行。每一条都带验算过程，你可以自己复算。

一个技能加两个只读的原生工具：

| 名称 | 类型 | 用途 |
| --- | --- | --- |
| `document-number-check` | 技能 | 指导通读材料、确认线索、重算，并按固定格式写出中文核对报告（错误、冲突、待确认三种结论） |
| `adds_up_extract` | 原生工具 | 读取 `.docx`、`.pptx`、`.xlsx/.xlsm`、`.csv/.tsv`、`.md/.txt`、`.pdf`，取出文字、表格和公式，按规则列出算术“线索”，并说明规则检验了多少、多少相符 |
| `adds_up_grim` | 原生工具 | GRIM 检验：报告的百分比或平均值，能不能由整数个数据得到 |

## 使用示例

- “帮我检查一下这份预算表里的合计、百分比和日期有没有对不上的地方。”（先给出文件的本机路径）
- “问卷有 25 份，平均分写的是 3.47，每份都是整数分，这个平均分可能吗？”
- “把这份汇报材料和后面的数据表对照一下，看看数字有没有前后矛盾。”

回答默认使用简体中文；你明确要求其他语言时按你的要求。

## 规则能识别什么

- **表格**：合计行和小计行与明细行对不对得上，合计列与左右各列对不对得上，平均行，“其中”行，占比列，百分比之和，按税率算出的行，行内的“数量 x 单价 = 金额”这类关系，同一列里混用单位。标签认“合计、总计、总额、共计、汇总、小计、平均、均值、其中”，同时保留对英语、德语、土耳其语、法语、西班牙语标签的识别。
- **正文**：“2026年3月5日（星期三）”这类日期与星期是否对得上，不存在的日期（如 2026年2月30日），“2026年3月1日至2026年5月31日，共 14 周”这类时长，“240 人中有 156 人，占 62%”这类个数与百分比，“从 12% 升至 15%，增长 3%”这类百分点与百分比。认全角的百分号和括号。
- **电子表格**：每个单元格的公式和显示值，`SUM` 区域少算一行、手填数字夹在两个公式之间、公式破坏相邻规律、文本形式的数字、错误值、隐藏的行和工作表、没有存储结果的公式。
- **数字写法**：同一文件里小数点与小数逗号并存，以及 `1,234` 这类有歧义的写法。

规则没有触发，不等于没有问题：规则只看得到表格和少数句式。技能会要求通读全文、对照摘要与正文、表格与图表，并说明没能核对的部分。

## 它做什么，不做什么

- 两个工具只读你指定的文件，不改文件、不写文件、不联网、不保存任何内容，不需要账号。
- 只拿文档和它自己比。不核实市场规模、汇率、价格这类外部事实，也不会凭记忆去“纠正”文档里的数字。
- 不读图片和扫描页里的数字（会如实说明是“未核对”）；不检验大写金额（由技能指导你读文时核对）；单位方面只在同一列里出现不同单位标注（如“万元”和“元”并存）时提醒，不做单位换算。
- PDF 的文字提取需要运行环境里已经装了 `pdfplumber` 或 `pypdf`；没有时工具会明说读不了，请直接阅读 PDF。旧版 `.doc`、`.xls`、`.ppt` 需要先另存为新格式。
- 安全上限：单个文件不超过 50 MB；Office 文件的压缩包条目不超过 5000 个，解压后单个条目不超过 80 MB、总共不超过 300 MB；含有 DOCTYPE 或 ENTITY 声明的 XML 会被拒绝。一次最多核对 10 个文件，报告过长会被截断并明确提示。
- “线索”只是候选，不是结论。这是第二双眼睛，不是审计；一份干净的报告只表示在能检查的范围内没有发现问题。
