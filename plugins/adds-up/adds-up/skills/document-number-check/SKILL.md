# 文档数字核对

核对材料里的算术和内部一致性，报告对不上的地方，并写出验算过程。默认用简体中文回答；用户明确要求其他语言时按用户的要求。

这项工作故意做得很窄：只管数字、单位、日期、个数，以及关于它们的说法是否互相一致。文字风格、语法、结构和论证质量都不在范围内，除非用户另外要求。

一次好的核对有三个特点：每条发现读者一分钟内就能自己验证（说清数字在哪、文档写的是什么、算出来是什么）；材料自己不能支持的内容一律不报，因为一次误报比漏掉一个四舍五入差更伤信任；最后说清覆盖了什么、哪些没能看到。

## 没有被点名要求时（顺带核对）

用户可能只是要审阅或校对，或者说马上要发出某份材料，或者你刚写完一份带计算结果的文档。这时用户没要数字报告，所以要简短。

- 只在材料里有可检验的数字时才做：表格、合计、百分比、计算过程，或者带星期的日期。没有数字就跳过；同一份没有改动的文件，在同一次对话里不要核对两遍。
- 做完整的核对（第 2 到 7 步），但只报告“错误”和“冲突”，放在你回答完用户真正问的问题之后，用一个小表，标题写 **文档数字核对**。不报“待确认”，不写验算过程，不写“值得一提”。最后加一句：“需要完整的数字核对报告（含验算过程和待确认事项），请告诉我。”
- 没发现问题时只写一行：“**文档数字核对：** 数字已核对，未发现错误（2 个表格，9 处数字）。”
- 文档是你刚写的：交给用户之前先改掉自己的错误，每处改动写一行，不要当作“发现”来报告。
- 用户说不要这类核对，本次对话里就不再做。

被点名要求时，完整执行下面的步骤和报告格式。

## 步骤

### 1. 拿到材料

用户指向什么就核对什么：附上或点名的文件、一批文件，或粘贴进对话的文字。如果请求没有指明任何可核对的材料，就问是哪个文件，其他什么都不要先问。默认值是：全部核对，用请求所用的语言报告。

### 2. 提取

对文件调用 **`adds_up_extract`**，参数 `files` 是文件路径列表（最多 10 个；路径必须是本机能读到的，绝对路径最稳妥）。它只读文件，不改文件、不联网。它能读：

| 文件 | 读取的内容 | 读不到的内容 |
|------|------------|--------------|
| `.docx` | 段落、表格、文本框、脚注、页眉页脚、图表里存储的数据 | 图片、批注、修订删除 |
| `.pptx` | 幻灯片文字、表格、演讲者备注、图表里存储的数据和图表类型 | 图片、图表背后嵌入的工作簿 |
| `.xlsx`、`.xlsm` | 每个工作表（含隐藏的）、存储的数值、每个单元格背后的公式、单元格的显示方式 | 图表、数据透视缓存、宏 |
| `.pdf` | 按页按行的文字、有表格线的表格，以及按数字位置推断的无线表格（环境里要有 pdfplumber 或 pypdf，否则会明说读不了，请直接阅读 PDF） | 扫描页和图片 |
| `.csv`、`.tsv`、`.md`、`.txt` | 全部内容，Markdown 表格按表格处理 | |

旧版 `.doc`、`.xls`、`.ppt` 读不了，请用户先另存为新格式。

返回的 `report_text` 对每个文件有四个部分：

- **内容**：每一行都带位置标签：`P12` 段落、`T3 R4 C2` 表格单元格、`S5 text 2` 幻灯片文字、`Sheet!B7` 单元格、`p3 L14` PDF 的行。
- **线索**，按阅读顺序：规则触发的地方，例如合计与分项对不上、乘积破坏了整列的规律、`SUM` 区域少算一行、星期与日期对不上。
- **规则覆盖了什么**：规则检验了多少个合计、行内计算、星期等，多少相符。这能说明“没有线索”意味着什么：一条什么都没检验的规则，什么也没有证实。
- **说明**：读了什么、没读什么、隐藏的行和工作表、有歧义的数字写法。

超过 60 行的长表只打印开头、结尾和有线索的行，规则仍然检查每一行。需要读中间各行时（例如找异常值），把 `all_rows` 设为 true；也可以用 `max_rows` 调整。输出过长时 `truncated` 为 true，要减少文件数或分批核对。文件类型不支持或工具读不了时，用别的办法读文件，继续核对。扫描页和图片里的数字，请直接看图，并在报告里写明这些数字是“目测读取”的。

材料只是粘贴的文字时，或者没有工具可用时，直接对文字核对。

**中文材料的识别范围**：规则按“合计、总计、总额、共计、汇总、小计、平均、均值、其中”等标签识别合计行和平均行，按“2026年3月5日”“星期三/周三”“共 14 周”“N 人中有 n 人，占 p%”“从 12% 升至 15%，增长 3%”识别日期、星期、时长和占比说法，也认全角的百分号和括号。别的叫法（比如把合计行叫“总盘子”）规则看不出来，只能靠你读。规则没有触发，不等于没有问题。

### 3. 通读，记下数字

要读完整内容，不能只看线索。规则只看得到表格和少数句式，看不到“摘要写 34%、图表写 36%”，看不到“五个区域”后面只跟了四个名字，也看不到“收入同比增长 12%”按表格算是 9.6%。

通读时，记下每个重要数字：它度量什么、单位、对应的期间和范围、出现在哪里。尤其留意同一个量出现了两次的所有地方。

### 4. 确认线索

线索是候选，不是发现。对每一条，去看它指向的单元格或句子，判断规则是否适用：那一行真的是那几行的合计吗？这些数是精确个数还是四舍五入的金额？“占比”列是占这个合计的比例，还是占别的东西的比例？然后自己重算。

不成立的线索丢掉。然后先弄清原因，再动笔：

- **合并同一原因的线索。** 一个错误的明细行，会带出错误的行合计、小计和总计。这是一条发现，把连带影响列在里面。
- **找出到底是哪个数错了。** 合计与分项对不上时，两边都可能是错的。检验依赖它的那些数：如果小计对不上，但总计等于正确的分项之和加税，那么小计是笔误，总计是对的。
- **说明可疑的数其实是对的。** 如果线索指向的单元格其实没错（比如总计只是因为旁边某个行合计错了才看起来不对），要在发现里写明它是对的、不应修改。线索里写着“连带影响”或“原因在这个文本单元格”的，指向的就是一个正确的单元格，应该放在它所指单元格的那条发现里，不要单独成行。
- **连带影响要用改正后的值重算**，再说它是连带影响。下游的数不一定就是错的。

### 5. 做规则做不到的检查

按 `references/checks.md` 一类一类过：句子里写的合计和派生数、百分比和增长率、平均数、个数和枚举、时长和截止日期、单位和数量级、正文对表格和图表、摘要对正文、基本统计、电子表格结构。用适合这份材料的类别，其余跳过。

当报告里给了百分比或平均值和样本量，却没给底层个数时，用 **`adds_up_grim`** 检验它能不能由整数得到：

- 百分比：`n` 填样本量，`value` 填报告的写法（如 `"37.5"`），`kind` 填 `percent`。
- 平均值：`kind` 填 `mean`，`value` 如 `"3.48"`。

这项检验适用于占 n 的比例，以及每个数据本身都是整数的平均值（量表分值、个数）。不适用于增长率、金额占比，也不适用于已经给出个数的情况（那就用个数除以 n）。n 很大且小数位很少时，几乎没有判别力。

### 6. 算，不要估

每一个和、积、比、百分比、日期差，都要当成一次计算来做。有计算工具时用代码：金额用 `Decimal`，日期用 `datetime`。没有时，把过程一步一步写出来，并在发现里标注“手算”。不要报告凭心算得出的数；结果让你意外时，换一种方式再算一遍再报。

### 7. 多个文件

给了多个文件时，把度量同一个东西（同一个量、期间、单位和范围）的数字跨文件对照。不一致就报“冲突”，两处位置都写出来。不要替用户判断哪个文件对，除非其中一个明显是另一个的来源（比如幻灯片是根据那份电子表格做的），这时写明这一点。

### 8. 报告

按下面的格式。

## 判断一条发现

每条发现给一个结论。

- **错误。** 文档自己的数字就能证明：分项和所列结果都在，而且对不上。
- **冲突。** 两处对同一个量写了不同的数，而材料没法判断哪个对。如果某个和或依赖它的数能判断（比如表格加起来等于两个值中的一个），另一个就是“错误”。
- **待确认。** 看起来不对，但答案取决于材料里没有的东西：数字是否四舍五入、某个词怎么定义、没给出的输入。写明什么能解决它。

一个手工填的合计与分项对不上，哪怕没有别的数依赖它，也是“错误”。要说明：材料无法显示是分项在填合计之后改过，还是合计本身填错了。

同一个原因既造成了已证实的错误，又造成了一处不一致时，只报一条，给较强的结论，顺序是：错误、冲突、待确认。材料指向某种解读但没有证明时，写明哪种解读能让数字对上，并说明这是“可能”而不是“已证明”。例如：“取 34% 时各块之和是 100%，所以图表里的数值更可能是笔误。”

**四舍五入。** 一组四舍五入后的数相加，可能与显示的各分项之和不同。有 n 个分项时，最坏情况下差额可达末位的 n/2 个单位，通常小得多；所以差 1 个单位很正常，4 个分项差 3 个单位就不正常。人数、件数、天数、次数是精确的，它们的任何差额都是“错误”。普通的四舍五入差不要列成发现。

**不用外部事实。** 只拿材料和它自己比。不要凭记忆去“纠正”市场规模、汇率、价格或临床数值。材料里推不出正确的数，就写明缺哪个输入。日历事实（某个日期是星期几、某月有几天）、单位换算和算术可以用。税率只有文档里写了才可以用。

**写法有歧义。** `1.234` 或 `1,234` 可以有两种读法，`03/04/2026` 这样的日期也是。按文档其余部分的读法去读，只有这种读法会改变某条发现时才说明。同一份文档里两种数字写法并存，只有读者可能读错某个数时，才算“待确认”。中文材料里 `1,200` 通常是千分位，但文档里没有别的线索时，规则会提示它有歧义，请结合上下文判断。

**中文材料常见的几处。** “万”“亿”“万元”“千元”和个位数混用要核对单位和数量级；“同比”“环比”“占比”“增幅”的基数不同，要确认用的是哪个基数；含税与不含税金额不要混着加；大写金额（如“人民币壹万贰仟元整”）与小写金额是否一致，规则不检验，由你读文时核对；“上半年”“前三季度”“第二季度”对应的月份，按文档自己的定义。

**不要改文件。** 核对以报告结束。用户随后要求改正错误时，只改商定的数字，其余原样不动，并列出每处改动。改法需要选择时（比如两个冲突的数哪个对），要问。

## 报告格式

用请求所用的语言回答。标题写“文档数字核对”。结论用词固定：错误、冲突、待确认，这样各次报告保持一致。

数字照文档的写法写。电子表格里，规则给出“显示为”的地方用显示值（“显示为 49.0%”），否则用带千分位的普通数字。运算符用 `x` 和 `-`，或者用户自己的文字里用乘号、减号就跟着用。

结构：

1. **标题和开头一句。** 开头一句数发现的条数，一条发现对应一个根本原因：“3 条发现：2 条错误，1 条待确认”，或者“14 条发现，全部是错误”。有影响文档主要数字时，再加一句说明影响。影响取决于某条发现怎么认定时，给一个范围。
2. **发现表。** 按结论排序（错误、冲突、待确认）。每个结论里，影响文档主要合计或核心论断的放前面，其余按阅读顺序。
3. **验算。** 每条发现一小段：计算、误差的大小和方向、连带影响，以及从文档里看不出来的东西。
4. **已核对 / 未核对。** 一两句话。大致数一数：表格、带数字的陈述、日期。“未核对”写没能读的内容（图片、扫描页），以及没有来源的输入，但只写带着核心数字的输入。
5. **值得一提**，只在适用时写，最多三条。凡是计算能证明有误的（包括星期、时长、个数）都是发现，要放进表里。这一栏放的是不算错误、但会让收件人停下来的事，比如隐藏行参与了某个合计、没写币种或单位、文档自己的数字之间出现看着不合理的关系（三个单位的成本高于收入）。写观察，判断留给读者。

到此为止。不要夸奖，不要泛泛建议，不要结尾再提供什么。

```
**文档数字核对：报价单-2026-117.docx**

3 条发现：2 条错误，1 条待确认。订单合计比应有的多 200.00。

| # | 位置 | 文档写的是 | 数字算出来是 | 结论 |
|---|------|------------|--------------|------|
| 1 | 价格表，“服务套餐”行 | 金额 7,400.00 | 15 x 480.00 = 7,200.00 | 错误 |
| 2 | 摘要，第二段 | “比二季度增长 12%” | (1,480 - 1,350) / 1,350 = 9.6% | 错误 |
| 3 | 分部表，“占比”列 | 占比合计 99.8% | 四个分项四舍五入可以解释 0.2 的差 | 待确认 |

**1. 服务套餐金额。** 15 x 480.00 = 7,200.00。表里写的是 7,400.00，多了 200.00。表里的合计 14,620.00 把所列金额加对了，所以带着同一个错误，应为 14,420.00。文档没有显示是数量、单价还是金额填错了。

**2. 比二季度的增长。** 三季度收入 1,480，二季度 1,350，都在区域表里。(1,480 - 1,350) / 1,350 = 9.6%，不是 12%。

**3. 分部占比。** 20.1 + 39.9 + 30.2 + 9.6 = 99.8。四舍五入会产生这么大的差。只有这些占比本应是精确值时才需要确认。

**已核对：** 3 个表格，14 处带数字的陈述，2 个日期。**未核对：** 第 4 页的图表是图片，读不到里面的数值。

**值得一提：** 报价单没写币种。
```

什么都没发现时，保留标题，用一句话说明，并给出覆盖范围：

```
**文档数字核对：团建预算.docx**

没有发现。我能检验的数字都与其他数字相符。

**已核对：** 2 个表格（行金额、合计、占比），2 处带数字的陈述，1 个日期。**未核对：** 没有遗漏未读的内容。
```

报告规则：

- 位置按读者的说法写：章节标题、表格标题或表格第一个表头单元格、行标签、幻灯片页码、工作表和单元格。Word 文件的提取里没有页码，所以用标题和行标签。工具的位置标签（`P12`、`T3`）可以放在括号里，但单独写没有帮助。
- 一个根本原因一条发现，连带影响写在里面。没有任何一处改动能让整张表对上时，把每个互相独立的差异各报一条，并说明它们可能有关联。
- 一处改动取决于另一条发现怎么认定时，用一句话说明。
- 电子表格要写明单元格并引用公式。一个主要合计受到不止一条发现影响时，在验算之后加一行说明合并后的影响。
- 待确认只放细心的读者会想确认的。二十条待确认会把两个真正的错误埋掉。
- 发现超过大约十五条时，先写改变主要合计的，其余按表格、幻灯片或工作表分组。
- 材料有哪些部分没能核对、为什么，要明说。没说出口的覆盖范围，读起来就是“全部没问题”。
