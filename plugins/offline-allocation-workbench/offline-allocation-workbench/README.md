# 离线资源配置优化台 1.0.0

在人工、机时等资源预算内，真实选择总价值最高的不可拆分作业。使用随包 HiGHS 1.16.0 本机引擎；独立复算选择、容量、最少作业数和目标值。交互页面可比较扩容前后方案，并保存项目、导出 CSV。

## 安装要求

- macOS **26 或更高版本**，Intel 或 Apple Silicon；Python **3.11+** 与兼容 WorkSwarm 原生插件 SDK、现代桌面浏览器。
- 本版仅提供经过核对的 macOS 通用引擎，不支持 Windows/Linux。不需要单独安装 NumPy、Node、HiGHS 或任何云服务。
- 原生安装 ZIP 的根目录是 `manifest.json`。在 WorkSwarm「扩展 → 我的扩展 → 本地上传」中导入并安装，随后在会话中启用本插件。市场外层 ZIP 不是此处的原生安装包。
- 本机求解使用系统 `sandbox-exec` 隔离网络；该组件不可用时拒绝求解，不绕过系统限制。首次调用会仅为哈希匹配的插件自带引擎恢复执行权限，不修改系统安装。

## 使用步骤

1. 创建一个本插件专用的已有本机目录，向会话提供完整绝对路径，并明确授权启动工作台。
2. 调用 `allocation_workbench`：`{"action":"start","workspace":"/你的/专用目录","confirmed":true}`。打开实际返回的本机链接。
3. 选择「资源选择」示例，点击计算。预期选 C+D，总价值 14；人工 5/7、机时 5/5。
4. 把机时容量改为 6，再计算。预期选 B+C，总价值 17；人工 7/7、机时 6/6。修改输入会使旧结果与导出失效。
5. 保存项目，刷新页面或重启工作台。项目会恢复，结果须重新计算。下载 JSON 可作为可移植备份。
6. 调整最少作业数为 3，默认预算下应报告不可行。有效可行结果才可导出 CSV；CSV 中公式开头的文本会被转义。
7. 测试完成后点击「关闭工作台」，或按授权调用 `allocation_workbench` 的 `stop` 操作。

也可直接调用 `optimize_allocation`，参数 `{"project":...}`，使用 `examples/资源选择.json` 内的完整对象。必须查看真实返回，不能将本说明的预期值当成计算结果。

## 输入格式与边界

顶层字段固定为 `schema`、`name`、`resources`、`jobs`、`min_jobs`，版本为 `offline-allocation/v1`。每种资源有 `id/name/capacity`；每项作业有 `id/name/value/uses`。`uses` 须列出所有资源标识。ID 不重复，名称最多 80 字，ID 最多 40 字，项目不超过 256 KiB。

资源 1–8 种、作业 1–100 项；容量、用量、价值只接受 0–1000000 的整数；最少选择数为 0 至作业总数。每项作业只选一次或不选。拒绝未知字段、重复 JSON 键、负数、小数、布尔冒充数值、外部路径及程序代码。标识和名称即使包含 HTML 字样也只作为文本显示。

## 如何理解结果

- **最优**：求解器报告零间隙最优，插件独立复算约束与目标；这不是形式化证明或对真实业务收益的保证。
- **可行但未证明最优**：资源约束满足，但计算停止前没有确定最优性。不能改称最优。
- **不可行**：当前预算与最少作业数无法同时满足。
- **未决/错误/取消**：没有确定结论，不等于不可行。不存在的目标界或间隙显示不可用。

固定单线程和种子，求解时限 5 秒、子进程墙钟最多 8 秒，另有 CPU/输出文件上限。大或困难项目可能未决。多个等价最优方案可以选择不同作业。不支持排程、先后依赖、概率、连续产量、负值或任意 LP/MPS/脚本导入。

## 保存、恢复和进程隔离

仅在指定目录的 `.offline-allocation-workbench/` 中保存私有状态（0700 目录/0600 文件），不把项目写入插件或宿主。保存或计算会持久化校验后的项目；结果不持久化。损坏项目原文件先保留，恢复时显示默认项目和警告；显式保存/重置前会备份损坏的原始字节。链接或权限异常会拒绝访问，请保留原文件并使用新的专用目录。

服务只绑定本机随机空闲端口，带本机访问令牌，不开放到局域网；请勿公开链接。进程关闭仅作用于本插件明确创建并核验的服务。禁用插件不会强制杀死用户已打开的独立服务；可点页面关闭或从原安装调用 stop。空闲 30 分钟退出，保存文件保留。
