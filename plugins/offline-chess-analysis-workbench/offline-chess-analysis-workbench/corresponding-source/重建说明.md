## Stockfish 构建方法

在独立目录复制 `stockfish.js/`，不要直接修改已安装插件。安装官方 Emscripten SDK **6.0.9**、Node.js 和 make，并按 Emscripten 官方方法使 `em++` 在当前终端的 PATH 可用。编译器属于通用开发工具，不随运行时分发。

在复制的源码目录执行；先把旁边的依赖锁文件复制为 npm 的标准名称：

```sh
cp ../stockfish-build-dependencies.lock.json package-lock.json
npm ci --ignore-scripts --no-audit --no-fund
MAKEFLAGS=TARGET_KERNEL=Emscripten node build.js --single-threaded --lite --no-split --strict-em-check -f
```

`package.json` 将 Terser 固定为 **5.51.2**；旁边的锁文件记录本次实际使用的完整 npm 闭包。`TARGET_KERNEL` 是原 Makefile 支持的变量：在 macOS 上明确选择 Emscripten，避免系统自动探测带入原生 Darwin 的 `-arch wasm` 和 `-mdynamic-no-pic`。这不修改上游文件。精确 lite 网络已在 `src/`，构建脚本可验证并嵌入它；不需要 full 网络。构建只使用单线程 lite 引擎；不启用多线程、ASM-JS 或外部残局库。原脚本可能在构建目录创建文件别名；这些别名不属于发布插件的路径。

输出为 `src/stockfish-19-lite-single.js` 和 `.wasm`。保留二者相邻且同名；工作台的 Worker 通过这个文件名解析 WASM。用新构建替换插件引擎时必须重新执行功能、浏览器、许可、动态脚本和完整打包测试，并获得新包的用户测试确认。不要根据旧测试的截图直接宣称新构建通过。

## chess.js 构建方法

在独立副本的 `chess.js/` 下用其锁定的 `package-lock.json` 与官方开发工具链执行 `npm ci --ignore-scripts`，再 `npm run build`。上游原构建配置和版本信息保留在该目录。其开发依赖只为重建使用，不进入插件运行时。
