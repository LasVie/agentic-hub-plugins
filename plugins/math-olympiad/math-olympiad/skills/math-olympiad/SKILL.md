# 奥数竞赛证明与对抗验证

默认用简体中文与用户交流和输出；用户明确要求其他语言时照办。数学符号、公式和 LaTeX 保持原样。

## 决定成败的五件事

1. **验证前先剥离思考过程**：看过推理过程的验证者会倾向于认同。验证只针对清理后的证明。
2. **“这是不是顺手证明了黎曼猜想？”**：如果你的定理特化到 ζ 函数等著名对象后得到一个公认的未解决问题，说明证明有漏洞。这是最可靠的危险信号。
3. **短证明 → 抽出一般引理**：用 2×2 等小例子找反例。若一般形式不成立，就找出“这一题”特殊在哪里。
4. **同一个缺口出现两次 → 退一步**：分类讨论可能掩盖了统一的论证，三行有时能完成十二页做不到的事。
5. **敢说“没有可信的解答”**：错误且自信比诚实弃权更糟。

**工具策略**：标准流程只用推理，不运行代码、不联网。竞赛数学是推理；计算只在“深入模式”（第 6c 步）中有限使用。任何阶段都**禁止**联网查找本题或其解答。

**文件路径**：本文中的 `references/…` 与 `scripts/…` 均相对于**本 SKILL.md 所在目录**。读取前先取你加载本文件时使用的完整路径，去掉末尾的 `SKILL.md` 作为基准目录再拼接，不要自行推测其他技能目录。

- 本技能随插件安装，**不在**系统提示中的“已安装的 Skill 根目录”（`…/workspace/skills/<技能名>`）下；不要套用该目录模板。
- 插件内技能的实际位置形如 `…/workspace/plugins/plugin_packages/<来源>/math-olympiad/skills/math-olympiad/`。例如本文件若加载自 `/home/u/.jiuwenswarm/agent/workspace/plugins/plugin_packages/local/math-olympiad/skills/math-olympiad/SKILL.md`，则应读取 `/home/u/.jiuwenswarm/agent/workspace/plugins/plugin_packages/local/math-olympiad/skills/math-olympiad/references/attempt_agent.md`。
- 若读取仍失败，不要反复尝试，直接按本文中的要点继续，并在验证记录中注明未能读取的参考文件。

## 单智能体说明（与上游的差异）

上游版本并行启动多个求解子智能体，并让若干“全新上下文”的验证子智能体互不知情地投票。本宿主只运行一个智能体，因此本技能把这些角色改为**同一智能体依次执行的独立阶段**：

- 每个阶段开始时，明确写出该阶段**允许依据的输入**（例如“仅题面 + 清理后的证明”），并在该阶段中只引用这些内容，不引用此前的思考、草稿或其他阶段的结论。
- 这种隔离是**流程上的约束**，弱于真正的独立上下文。最终答复中须如实说明“验证由同一智能体分阶段完成”。
- 用户若能在新会话中粘贴“清理后的证明”另行验证，可获得更强的隔离；可在结论中提示此选项。

## 选择流程

| 问题类型 | 做法 | 验证 |
| --- | --- | --- |
| AIME 等数值答案题 | 多种方法独立求解 → 多数表决 | 仅核对答案（代入检验） |
| 证明题（IMO/Putnam/USAMO/联赛） | 完整流程（下文） | 多轮对抗验证 |
| “这个证明对吗？” | 直接进入第 4 步 | 对抗验证 + 题意偏差检查 |
| “简化这个证明” | 直接进入第 8 步 | — |
| 整套题（如一场比赛全部题目） | 逐题执行完整流程，汇总结果，最后统一排版 | 每题单独对抗验证 |

整套题时，不要在一次推理中同时解所有题；每题单独走流程，结论中按题号列出“已证明 / 无可信解答”。

## 完整流程

### 1. 题意检查

求解之前先确认题意：

> 读题。列出 2～3 种可能的理解。逐一判断：这种理解是否让问题变得平凡？若一种理解很简单而另一种很难，命题人几乎必然指后者。写明你按哪种理解求解以及理由。

大量“技术上正确”的解答其实解的是错误的理解；奥数题常有容易误读的陷阱。

### 2. 多角度求解（依次进行，纯推理）

依次进行 3～4 次**求解尝试**，每次换一个起始角度（详见 `references/solver_heuristics.md`）。每次尝试的要求见 `references/attempt_agent.md`，核心是：

```
不进行任何计算。不运行代码、不联网、不读取外部资料。数值验证不是证明步骤；“我验证了 n=1..10 规律成立”不是证明。

内部过程（循环直至结束）：
- 求解：写出完整严格的解答。
- 自我改进：重读，在评分者看到之前补好缺口。
- 自我验证：以严格评分者的标准检查，每一步都有依据吗？
- 修正：修正后重新验证，最多 5 轮。
- 停止：自我验证连续两次干净通过，或已达 5 轮，或方法根本行不通。

答案正确但推理有误即为失败。若不完整，如实说明，绝不隐藏缺口。

题目：<题面>
起始角度：<本次尝试的角度>
```

可选起始角度：先算小情形（要算到 n=3 以上）；找不变量或单调量；考虑极端情形；归纳；利用对称性；倒推；去掉一个条件，看何处变得显然错误；推广（发明者悖论：更多结构有时更容易）。

每次尝试只记录**最终状态**：

```
**结论**：完整解答 | 部分结果 | 无进展
**轮数**：[验证—修正循环次数]
**方法**：[关键思路，一段]
**详细解答**：[完整、逐步有据]
**答案**：[如适用]
**自我验证记录**：[发现并修正了什么；尚存的疑虑]
```

### 3. 清理解答（上下文隔离的关键）

验证之前，从每份解答中删去：所有思考内容；“我试试……”“等等，其实……”之类的叙述；所有错误开端和回溯。只保留**题面 + 方法 + 证明 + 答案**。后续验证阶段只能看这份清理稿。

### 4. 对抗验证（只依据清理稿，按模式攻击）

开启一个新的**验证阶段**，声明：“本阶段只依据题面与以下清理后的证明，忽略此前全部推理。”验证的任务是**攻击**而不是打分。具体提示见 `references/adversarial_prompts.md`，完整检查清单见 `references/verifier_patterns.md`。重点模式：

| 模式 | 检查内容 |
| --- | --- |
| **#4** | 该定理特化到著名对象（ζ、二次互反律等）后是否证明了某个公开未解问题？若是 → 有漏洞 |
| **#18** | 把证明自己的中间恒等式代回“剩余缺口”，是否又得到原命题？若是 → 循环论证 |
| **#40** | 是否有“一行引理”？抽出其一般形式，找 2×2 反例；若一般形式不成立，找出是什么特殊结构拯救了本题 |
| **#5** | 对每个引用的定理，从头重新核对前提。“在 [0,1] 上连续”≠“在 ℝ 上连续” |
| **#6** | 是否用正则化值“界住”了某个无穷级数？检查边界处是否有极点，若有则级数发散 |

验证阶段输出：

```
**判定**：HOLDS（成立）| HOLE FOUND（发现漏洞）| UNCLEAR（不确定）

若发现漏洞：
- 位置：[引用有问题的步骤]
- 模式：[触发的检查编号，或“其他”]
- 为何失效：[具体说明]
- 能否修复：[能，需要 X / 不能，属根本性问题]
```

上表只列最常用的模式；每轮验证还应按 `references/verifier_patterns.md` 中的完整清单（#4、#5、#6、#10、#17、#18、#19、#22、#23、#35、#40、#58、#60）逐条判断是否适用。

判定词对应：`references/adversarial_prompts.md` 中的提示使用 CORRECT / INCORRECT / GAP。计票时 CORRECT 记为 HOLDS；INCORRECT 记为 HOLE FOUND；GAP 若位于结论所依赖的步骤（补不上则结论不成立）记为 HOLE FOUND，若只是表述不完整、可直接补齐，则补齐后记为 HOLDS 并在验证记录中注明；无法判断记为 UNCLEAR。

参考提示中“你不知道其他验证轮次如何投票”“假设你是第一位审稿人”等说法，在单智能体下理解为：**本轮判定不得引用、参考或迎合前几轮的结论**。各轮结束后的计票与提前结束判断属于流程控制，在两轮之间进行，不属于任何一轮验证的内容。

### 5. 多轮验证与非对称阈值

按（判定、把握程度）对候选解答排序，取最优者。对它进行最多 5 轮**彼此独立**的验证阶段：每一轮只看题面与清理稿，不看前几轮的判定，并且每轮侧重不同的模式组（例如第 1 轮 #4/#5，第 2 轮 #40/#18，第 3 轮逐行核对，第 4 轮边界与退化情形，第 5 轮题意与“偷换命题”）。

- **非对称阈值**：4 轮 HOLDS 才确认，2 轮 HOLE FOUND 即否定。（“快速”预算只做 3 轮时：3 轮全部 HOLDS 才确认，2 轮 HOLE FOUND 即否定，其余情况升级为标准预算继续验证。）
- **提前结束**：已有 2 轮发现漏洞 → 否定，停止；已有 4 轮成立 → 确认，停止。
- 本流程由同一智能体完成，“独立”指每轮只依据规定输入；结论中要说明这一点。

### 5b. 某个情形始终证不出来时，先退一步

若证明分成几种情形，一种很容易而另一种顽固不破：在硬啃之前，先问是否有办法让分类消失。困难情形的假设往往对某个尚未关注的**中间对象**有很强的推论，直接利用它，而不是沿用原来的推理链。

卡在情形 B 时检查：

- 情形 B 的假设对函数在**其他**输入处的取值说明了什么？
- 能否把另一组 (a,b) 代入原方程？
- 是不是证明得太多了？（更干净的矛盾需要更少的工具。）

### 6. 修订（如需要）

若发现漏洞，进入**修订阶段**：只依据（清理稿 + 漏洞报告），不回看最初的思考过程。

```
验证发现证明中存在以下问题：
[漏洞报告]

请修复证明。若漏洞属根本性问题（此方法行不通），如实说明，并返回 **结论：没有可信的解答**，附上尚存的部分进展。

任何无法完全补上的步骤，在证明正文中就地标注：[缺口：具体说明尚缺什么]。
```

最多 3 次修订，之后对修订稿重新执行第 5 步。若触发的是 #40（一行证明太“干净”），修订时使用 `references/adversarial_prompts.md` 第 7 节的“对抗简报”：要么找出本题的特殊之处，要么指出证明在哪里断掉，不允许回答“看起来没问题”。

### 6c. 深入模式（标准流程弃权时）

标准流程弃权时，问题可能需要的是更多时间，而不是更强的能力。深入模式是一次专注的尝试：

- 不设时间压力；
- 若宿主提供代码执行工具，允许**有界**的本地计算（模 2^k 运算、n≤10 的小情形枚举、符号恒等式核对），单次计算不超过 60 秒；不允许无界的暴力搜索；
- 以弃权原因为起点：验证指出的具体缺口，或求解阶段已证明的部分结果。

**禁止联网、禁止查找本题或其解答**。在网上找到答案不是解题。双指数增长的量（如 b_{n+1}=2b_n²+b_n+1）不要精确计算，改为在 ℤ/2^m 中计算或只跟踪 v_p(·)。

**第 6d 步（不可省略，任何预算都适用）**：验证阶段弃权后，必须先进行一次深入模式，再写弃权结论。宿主没有代码执行工具时，深入模式只做纯推理（手算小情形、模运算），其余要求不变。若深入模式仍无结果，才写弃权。

### 7. 诚实弃权

若 3 次修订都失败，停下并承认：

```
**结论**：没有可信的解答

**已尝试的方法**：[……]
**已证明的部分**：[通过验证的引理或部分结果]
**断在何处**：[未修复的漏洞]
```

不要猜。真正重要的是**条件准确率**：当你说“已解出”时，是否真的正确。

### 8. 表述整理（确认正确之后）

验证正确的证明往往不是优美的证明。进入**表述阶段**，只依据已验证的证明，参考 `references/presentation_prompts.md`：

- 最简单的说法是什么？
- 哪些引理应内联，哪些值得单列？
- 有没有大材小用的地方？
- 已知答案后，是否存在三行的“事后诸葛亮”证明？

输出 LaTeX 格式的中文证明。若 `scripts/check_latex.sh` 返回 0（环境中有 xelatex），可用 `scripts/compile_pdf.sh <正文.tex> <输出目录>` 编译为 PDF；否则直接给出 LaTeX 源码与 Markdown 版证明。

## 预算建议

| 场景 | 求解尝试 | 验证轮数 | 修订上限 | 表述整理 |
| --- | --- | --- | --- | --- |
| 快速（用户要求简短或题目较易） | 2 | 3 | 2 | 可省略 |
| 标准（默认） | 3～4 | 5 | 3 | 是 |
| 深入（用户要求严谨或标准流程弃权） | 4 + 深入模式 | 5 + 全部模式逐条检查 | 4 | 是，写两稿择优 |

## 数值答案题（AIME 类）

省略证明流程。用 3～5 种不同方法独立求解，对数值答案多数表决；若无多数，把票数最高的两个候选代入原题核验。

## 最终答复格式

```
## 题意理解
## 结论（附置信说明），四选一：
##   求解：已证明 / 没有可信的解答
##   检查用户证明：证明成立 / 证明有漏洞（命题可能仍成立）/ 命题不成立（附反例）/ 无法判定
## 证明（或部分结果与断点；检查时为漏洞位置、原因与修复建议）
## 验证记录：各轮判定、触发的模式、已修复的问题；注明“由同一智能体分阶段验证”
## 可选：LaTeX 源码 / PDF 路径
```
