# 重建、修改与替换 Verovio

源码基于 Verovio 6.4.0，提交 `cb5fcfa1178238138aa7f51f1e55f6a743eb26cc`。此目录含对应的 C++ 首选源码、生成属性类所需的 LibMEI 源码及 ODD 数据、工具链接口、浏览器模块源码、嵌入字形资源、构建参数和 npm 锁文件。完整许可及署名见随插件分发的 `licenses/`。

1. 将此源码解压到独立的可写目录。使用 Emscripten 4.0.23（源码提交 `7a5d93b50f6a3a35e85a0d2fc9e667b8498e6aed`，官方编译器发行标识 `aaa43392544d695232b70eda706d751f18980c2a`）、CMake 3.31.8、Make 与 Node.js/npm 22.16.0。构建工具按各自官方说明独立准备。npm 构建依赖见锁文件，安装步骤禁用生命周期脚本。运行插件无需这些构建工具。
2. 运行 `sh rebuild.sh`。它构建静态库，链接无 JavaScript 动态执行的 WASM 模块，然后生成 `emscripten/build/verovio-toolkit-wasm.js`。该模块仅嵌入此包的本地数据。编译器版本、平台或源码变更可能改变输出字节。
3. 需要重建版面度量时，用 Python 3 与 FontTools 4.55.3 执行 `python tools/generate_text_metrics.py fonts/liberation-2.1.5 emscripten/data/text`，然后重建。常规重建可使用随源码分发的 XML 版面度量。TTF 文件仅用于重建输入，不嵌入模块，也不作为界面字体加载。
4. 用户可以在自己的可写插件副本中替换 `web/vendor/verovio-toolkit-wasm.js` 为保持同一 JavaScript 接口的修改版，然后重新打包导入 WorkSwarm。工作台按固定相对路径加载独立的引擎文件，未对其内容签名或设置字节校验锁。用户可修改 LGPL 引擎，并为调试这些修改进行逆向工程。团队重新分发修改后的包时，须重新测试并更新相应许可材料和来源记录。

本构建关闭 Humdrum、MXL、ABC、GABC、PAE。保留 Verovio 原有图形编辑接口以满足编译依赖，工作台并未调用此接口。使用 Leipzig、Bravura 字形轮廓与重新生成的版面度量，省略旧 Liberation Serif 1.04、嵌入 CSS 字体及未使用的字体和页脚图像。
