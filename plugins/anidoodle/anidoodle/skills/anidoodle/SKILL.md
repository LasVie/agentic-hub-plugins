# 手绘交互工坊

用户要制作交互插画、手绘网页角色或滚动绘画时使用。优先利用现成工具完成可打开的作品，不把概念说明当成交付。默认使用简体中文，尊重用户明确指定的其他语言。

## 先确定作品

只澄清缺失且必要的信息：场景与实际输出工作区。已知工作区就使用真实绝对路径，不杜撰目录、不把插件安装目录作为输出位置。用户说“你决定”时可以选 `mascot` 并拟定简短中文标题。

调用 `anidoodle_art(action="list")` 可查已支持场景：

- `mascot`：铅笔水彩机器人跟随指针；点击“欢呼”“挥手”或角色会产生反应。
- `form`：演示填写表单、密码遮眼与成功反馈。只用虚构信息，不引导用户输入真实密码。
- `scroll`：用户滚动推进逐笔绘画。

## 实际生成

调用 `anidoodle_art`，`action="create"`，提供 `workspace`、英文文件名前缀 `name`、`scene`，以及可选 `title`（80 字符内）与 `description`（600 字符内）。名称不含扩展名。已有文件不能覆盖：改用新文件名后重新调用。

成功后给出返回的真实 HTML 文件链接，并说明鼠标/键盘/滚动操作及页面下方的 PNG 导出按钮。用户应使用 Chrome/Edge 打开；不能保证宿主内嵌预览。不要宣称做了未实际执行的视觉测试。

## 修改和扩展

修改标题/说明可重新生成。改变角色外形、绘画方式或交互逻辑需要源码修改，不得仅改标题后声称换了角色。

当用户需要创作新角色或改编交互，调用 `action="source"` 导出完整选定源码工程，阅读其中 README，修改 `Piece` 和页面再编译。读取用户文件或执行构建遵守宿主权限；不自动下载额外音色或全量上游。保留 Apache 许可、NOTICE 及修改声明，并让生成的 HTML 带完整许可。

任意新画面能否实现，应依据实际代码和渲染检查回答。首版不是上游全部 32 画风的移植，也不提供 MP4/GIF/配乐。视频成片、分镜和音频继续使用已有 Remotion/分镜工具；本插件补充交互素材与逐笔绘画。
