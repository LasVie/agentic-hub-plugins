# 流动效率与持续成本测算

两类项目与服务工作中常用的测算，各配一个原生计算工具和一个技能。每一步都带代入数字的公式，你可以自己复算。

| 技能 | 原生工具 | 用途 |
| --- | --- | --- |
| `flow-efficiency` | `flow_cost_flow_efficiency` | 由周期天数和实际处理小时数算流动效率、等待时间，比较“处理加快”和“等待缩短”两个杠杆各节省多少个工作日 |
| `business-case-running-costs` | `flow_cost_business_case` | 一次性成本、每年运行成本、每年收益和期限（3 或 5 年）：运行成本占比、回收期、投资回报率、盈亏平衡用量与盈亏平衡成本超支，以及用量偏低、成本超支两种偏离的结果 |

## 使用示例

- “一个变更申请从提出到上线用了 42 个日历日，实际动手处理 16 小时，流动效率是多少？”
- “项目 18 万元，每年运行成本 2.4 万元，每年收益 15.08 万元，按 3 年算，这个商业论证成立吗？”
- “我们 12 个工作日关闭一个变更请求，只有 30 小时在真正处理，时间花在哪了？”

回答默认使用简体中文；你明确要求其他语言时按你的要求。金额只是数字，货币或单位由你决定（默认显示“元”）。

## 它做什么，不做什么

- 两个工具只做算术：用精确的有理数运算，只在显示时四舍五入。不联网、不读写文件、不保存任何内容，也不需要账号。
- 工具会拒绝对不上的输入（例如处理小时数超过周期内的工作时间、收益为 0、成本全为 0），并请你确认，而不是自己改数字。
- 本插件**故意不给“正常值”或经验法则**，因为没有可靠来源。结果只描述你自己的数字，不评价好坏；可靠的比较对象是你自己的流程，过几周再测一次。
- 局限：流动效率对单个事项只是数量级参考，不评价个人或团队；日历日按 5/7 近似折算，节假日不扣除。商业论证没有折现、收益没有爬坡期、比较对象是“保持现状不变”、不含税和折旧。一个数字还不是商业论证，真正的内容是数字背后的假设。
- 测算结果不能替代财务、控制或流程分析。
