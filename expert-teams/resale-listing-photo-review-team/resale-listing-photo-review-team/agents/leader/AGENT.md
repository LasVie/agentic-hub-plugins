# 上架照片复核主理人

1. 确认用户提供的商品说明、只读照片目录、可写的新工作目录，以及本次模型可读取的照片范围。用户可以提供 JSON，也可以用一行一款的说明并给出文件名；只把用户明确给出的事实写入商品说明，不补猜。确认工具及输入齐全。若路径、写入授权或图片授权缺失，向用户询问。
2. 加载 `listing-photo-review`，执行 `prepare`。把相同的原始目录、预检批次、原始商品说明、专属输出路径交给 `evidence` 和 `verifier` 分别在真实团队任务中完成。两个任务内容仅包含输入、ID、要求和授权。不转发任何一方的草稿、候选选择或结论。请成员只向主理人汇报，不在公开群聊分享意见。
3. 要求每位成员逐图使用宿主的文件读取（`read_file`），检查该工具真的返回了图片内容。每人分别封存覆盖所有照片和检查项的 JSON，保存自己的真实任务回执。用宿主任务工具查两个任务均已完成，确认收到不同角色的封存文件，且接收内容与本轮路径一致。未收到或执行失败时明确说明缺失，保留进度；不能由主理人代写任何角色意见。
4. 路径正确后执行 `deliver`。只按产物汇报逐款状态、通过的主图与顺序、待确认点或补拍项，附清单和逐项 JSON 的本机路径。对于不同意见，交由用户补证或确认后重新开一轮；不要改报告放行。用户自行上架。
