# 基金申请书专家团

按资助方指南写基金申请书：拆解评审要点、调研文献与研究空白、设计方案与预算、模拟评审打分，逐项校验后交付申请书草稿、自评表和待补清单。

## 成员

| 成员 | 角色 | 主责 |
|---|---|---|
| `leader` | 申请书主理人 | 确认需求、分派任务、撰写正文、以工具结果验收 |
| `call_analyst` | 指南解读师 | 评审要点（带权重）、篇幅限制、预算规则、形式要求 |
| `literature_scout` | 文献与空白调研员 | 检索真实文献，写研究现状与研究空白 |
| `methods_budget_planner` | 方案与预算规划师 | 目标、技术路线、里程碑、风险预案、可复算的预算 |
| `mock_reviewer` | 模拟评审专家 | 按细则逐条打分、列出薄弱项与修改意见 |

顺序是硬约束：评审要点没定不写正文；预算没通过校验不交付；`review` 未返回 `ready_to_submit` 不称“可以提交”。

## 配套工具

`proposal_checker`（leader、call_analyst、methods_budget_planner、mock_reviewer 使用）：

- `criteria_map`：每条必需要点都要有章节覆盖，证据引文须逐字出现在章节正文中。
- `budget`：数量 × 单价 × 年数、合计、总额上限、类别占比上限、缺少依据的预算行。
- `limits`：按章节与全文统计篇幅（中文按字、英文按词）。
- `score`：模拟评审加权得分率与薄弱要点。
- `review`：一次运行全部检查，给出 `ready_to_submit`。

工具只做文本与算术核对，不联网、不写文件、不判断科学价值。文献检索使用宿主提供的搜索能力。

## 全团共同加载的 rail

`GrantProposalRail` 在每次模型调用前注入证据边界：评审要点只来自指南原文；只引用真实检索到的文献；前期成果只用用户材料；只有工具通过才可称合规；不代用户提交。

## 示例提问

- 我要申请国家自然科学基金青年项目，主题是低资源语言的检索增强生成，帮我写申请书初稿
- 这是申请指南和我的草稿，按评审要点帮我做一次模拟评审并列出修改清单
- 帮我核对这份三年预算，总额上限 50 万元，设备费不超过 30%

## 边界

不预测资助结果；不代替资助方的形式审查；不编造文献、前期成果或资助方规则；不代用户在申报系统提交、签字或付款。
