# 家校通知变更与待办核验专家团

把家长给定的班级群消息、邮件和门户通知整理成本周清单。适合每周汇总，也可在收到更正时重跑。使用 WorkSwarm 现有专家团任务、文件和命令工具，以及 Python 3.10 以上标准库。

## 输入及查看范围

粘贴通知，或提供一份采用随包 examples/weekly-notices.json 格式的本地 UTF-8 JSON。粘贴内容由主理人先转录，再确认范围和来源。可用孩子或班级代号，无需真实姓名、账号或原件照片。旧清单可用于提醒主理人查找原始通知，以原始通知为更新依据。

| 字段 | 含义 |
| --- | --- |
| start / end | 要列出的任务日期范围，含首尾，最多 31 天 |
| children | 1 至 10 个代号，每项有 label 和可空的 caregiver，后者只用用户明确输入 |
| notices | 1 至 40 份原始通知，按代号组织，每份不超过 100 行且不超过 4000 字符；总摘录最多 200 条 |
| sent / issuer | 原始发布时间及发文方；支持 YYYY-MM-DD、YYYY-MM-DDTHH:MM 或 null；发文方用同一可信来源的明确名称 |
| scope / text | 适用的孩子代号列表；不明确填 null，不适用填空列表；text 原样保留消息和换行 |

明确日期支持 YYYY-MM-DD 或中文年月日。仅月日须在核对范围内对应唯一日期。“今天”“明天”“后天”“本周四”“下周一”等以原发文日期为基准。仅写“周四”或缺少原始发文日期时保留待确认。时刻可写 16:30、“下午5点”或“下午5点半”，用同一学校当地时间；原文未给具体时刻不自行设定。相同发文方同日更正如缺少明确时分，保留待确认。多个更正若同时指向同一旧版本，或无法确认所指事项，需要用户澄清。

## 分工和交付

1. 主理人确认通知、范围和新输出目录；分析员与核验员各自从原文生成逐项摘录。
2. 核验员先交独立基线，后比对分析员初稿，检查引用、遗漏、日期及更正只作用于所属班级。真正影响结果的分歧移入待确认。
3. 主理人使用当前独立核验回执交付中文 checklist.md、changes.csv、audit.json。旧安排留在变更记录。清单不读学校账户、不自动推送，也不改变外部日历。

首次试用请导入中文原生 ZIP 到 WorkSwarm 专家团。用获授权的模型，以随包虚构例子运行。确认甲班接送变成 17:00，乙班仍为 16:30，乙班体育用品已取消，缺原发日期的“明天”进入待确认。
