# 问卷跳题核验流程

1. 在可见回复中确认授权输入 JSON 与空输出目录的绝对路径。若已明确提供则直接开始；仅在用户明确同意时用内置虚构样例。确认 Python 和团队的 `scripts/routing.py` 可由宿主调用。缺参数时只询问缺项，不猜测。
2. 创建任何团队任务前，负责人亲自调用本地命令 `python -B <包内脚本绝对路径> validate <输入绝对路径> <输出目录绝对路径>`。预检只读，不得作为任务分派；收到实际退出码 0 才能继续。非零退出或命令无法执行时，在主会话一次性给出实际错误，然后结束本次运行。不创建基线或诊断任务、不写结果、不重试、不发送等待消息。
3. 预检成功后，只创建一项任务：交给 `verifier` 的 `baseline`。提供原始输入、包内脚本和输出目录。收到完成通知后确认任务已完成、脚本退出码为 0、`baseline.json` 已生成且哈希对应。基线成功后另一次调用仅创建 `analyst` 的 `analyze`，不传基线结论。确认分析完成、`analysis.json` 可读且哈希匹配后，再创建同一 `verifier` 的 `verify` 任务。此时才允许核验员读取分析结果并回放证据。
4. 任一已派任务报告非零退出、缺少交接文件或核验失败时，不等成功回执，也不再分派。检查该任务的实际状态；若仍未结束，由负责人使用宿主的 `update_task` 将该任务 ID 的状态设为 `cancelled`，并用 `view_task` 核实。不要取消其他任务或把失败标成成功。若宿主不提供该工具或拒绝取消，在最终回复说明实际错误及未能关闭的任务；停止，不轮询、不重试、不发送重复状态消息。
5. 核验任务完成且 `verification.json` 和三份交接文件均有效后，负责人亲自调用本地命令执行 `report`，不再创建报告任务。报告命令失败时在主会话给出实际错误并结束，不自行补写报告。成功后交付 `报告.md` 的实际绝对路径、三类缺陷计数及主要重现路径；区分可能循环和必然卡死，不评价题目措辞或业务意图，不修改问卷文件。默认中文。
