# WorkSwarm 集成测试

1. 核对原生 ZIP 的 SHA-256（见 `release/1.0.2/artifact.json`）。在 WorkSwarm 打开 Experts → My Experts → Expert Teams → Create → Create from file，选 1.0.2 原生 ZIP，而不是 Hub 包。确认运行的是新版、模型可用，且本机有 Python 3.10+。
2. 把同一原生 ZIP 的 `examples/演示问卷.json` 解压到测试目录并创建空的结果目录。在新会话明确提供两者的绝对路径。可复制：

   > 请使用问卷跳题逻辑核验专家团读取我授权的虚构问卷 JSON：输入文件为［绝对路径］，空输出目录为［绝对路径］。请按团队流程真实分派成员，回放证据并用简体中文报告。

3. 在 Task Planning 检查独立核验员完成基线后才创建分析员任务；分析完成后再创建核验任务。负责人直接生成 `报告.md`，不创建报告任务。应生成三份 JSON 和 `报告.md`。应找到不可达 Q3；Q2 的“缺失分支”指向未定义 Q99（先选“继续”）；Q1、Q2 各有一个可返回同题的循环证据；合法退出仍可用。
4. 将 WorkSwarm 首选语言设为简体中文，在新会话及新输出目录使用 `tests/fixtures/duplicate-option.json`。应在主会话以中文解释一次错误（`重复键`）后结束，不创建任何团队任务（包括基线），不再发送等待消息，输出目录保持为空。Task Planning 若未出现，保存显示错误及运行结束的完整界面原图即可。另试不提供路径的请求：应先说明缺项。
5. 保留原始截图：已导入的团队、真实任务分派、中文报告及阻塞案例。只确认实际测试过的 ZIP 版本及哈希。
