# 家务轮值与负担复核专家团

版本 **1.0.0**。把已经约定的一周家务安排给家庭成员或合住伙伴，分别完成资料梳理、轮值规划和独立核验，交付可直接打开的中文周历、CSV 和审查记录。

## 安装和第一次使用

需要 Python **3.10+**、支持原生 AgentGroup 的 WorkSwarm，以及已允许使用的模型和宿主文件、命令、团队委派工具。程序只使用 Python 标准库；不安装 OR-Tools、AutoGen、SDK 或额外服务。

在 **专家管理 → 我的专家 → 专家团 → 创建 → 上传文件创建** 上传本版原生 ZIP。确认它显示为专家团，包含 `leader`、`analyst`、`planner`、`verifier` 四位成员。市场包装 ZIP 不是此处的原生 ZIP。

可以先发送：

> 请使用家务轮值与负担复核专家团1.0.0，读取随包 examples/shared-home.json 作为我明确授权采用的虚构示例，把各阶段证据和最终文件保存在我指定的新目录。请真正委派梳理员、规划员和独立核验员，分别读取自己的技能并运行随包脚本。对照案例列出人员、分钟数、日期和上限，保留偏好未满足项。复核员须独立复算并说明内容是否可接受，不能由主理人代写成员意见。只在全部约定检查和内容复核均通过时给出通过结论。

开始前还须给出一个**已存在的工作父目录的绝对路径**。各阶段创建不同的、尚不存在的子目录；不覆盖已有资料。使用真实家庭资料时，只提供你有权交给所选模型处理的内容。

也可直接用中文描述人员、家务和限制。资料梳理员把明确的原话整理为案例；未知的耗时、资格、日期或上限须在可见正文询问，不替用户猜测。已明确给出的事实不用重复索取确认。所有人是否接受安排由用户判断，结构化输入或程序通过均不能替代同意。

## 分工与交付

| 成员 | 工作 | 交接物 |
|---|---|---|
| 轮值主理人 `leader` | 确认范围、创建真实任务、核对分歧和最终交付 | 通过版或明确标注的待澄清草稿 |
| 家务资料梳理员 `analyst` | 对照用户原话整理家务与限制，运行输入核对 | 原始案例、intake.json、来源与未知项说明 |
| 家务轮值规划员 `planner` | 按约定限制编制分配，解释负担和偏好取舍 | plan.json、规划说明 |
| 独立负担核验员 `verifier` | 从原始案例独立核对每项任务和每人分钟数，再审阅内容 | review.json、review-notes.json |

最终三个文件：

- `rota.html`：七日家务周历、负责人、约定分钟数、负担表和待澄清项；离线打开，无外部资源。
- `assignments.csv`：同一轮分配，可用表格软件打开；草稿状态明确写入每行。
- `review.json`：当前输入快照、文件摘要、独立复算和内容复核说明。程序不证明成员实际参与，仍需查看宿主的团队任务和工具记录。

## 支持的范围

- 连续七天，2–6名参与者，1–21次家务。每天重复的家务按不同编号逐次列出；`day=0` 是开始日期，`day=6` 是第七天。
- 家务耗时为1–480的整数分钟。每人的七个每日上限为0–480，每周上限为0–3360。上限是允许的最大值，不是必须做满的目标。
- 每次家务列明可承担人员、偏好人员；不可用日不能分配。空的可承担名单可以表达当前无人能做，由团队说明阻塞，不擅自扩大资格。
- 偏好是软约定，不能覆盖资格、不可用日及分钟上限。偏好未满足须显示，不偷偷删除。
- 只按“日”安排，不处理精确钟点、同时占用设备、多人共同完成、自动多周轮换、外部日历、后台提醒或自动执行家务。

规划器先处理选择少和较长的任务，再优先尝试本周已排分钟相对上限较低的人员，随后考虑偏好与稳定顺序；必要时回溯。找到首个可行结果即停止，**不声称最优**。默认最多搜索100000节点：穷尽与达到上限分开报告，达到上限是未决，不等于无解。负担只是约定分钟数，不能衡量全部体力、心理或照护责任，也不证明家庭公平。

完整案例和报告格式见共享技能的 `references/input-format.md`。脚本经宿主已有命令工具执行，不会自动成为另一个已注册的原生工具。成员各自读取私有工作流技能，共享技能对所有成员可见；角色分工不是文件系统安全隔离。

## 问题与停止条件

缺少重要输入先澄清；原始输入或规划报告改变后，旧报告失效。遗漏、重复、未知编号、资格/日期/分钟冲突、报告总数不符或内容复核阻塞不能获得通过结论。最多修正一轮，仍有问题则交付待澄清草稿或说明未完成，不虚构成员结果、文件路径、最优解或人工测试通过。

来源为独立设计，研究参考列于开发目录 SOURCE_REVIEW.md；不包含第三方实现、框架、私人案例或付费服务凭据。数学检查、真实成员执行和用户实测是三种不同证据。
