# Native design: Warehouse Stocktake Reconciliation Team

Start with a single offline stocktake containing three authorized UTF-8 CSV files. Each `(sku, location)` has a book snapshot and a physical observation in the same unit. Movement rows have a globally unique ID and signed delta at an explicit-offset timestamp. Book counts include events at the snapshot time. The observation includes events at its observation time. Use movements in `(snapshot time, observation time]`; simultaneous count/movement inclusion must be confirmed before running. The user must confirm complete logs over each interval. Do not infer coverage or resolve mismatches by treating missing inputs as zero. v1 supports whole units only, one observation per key, no lots, unit conversion, valuation or inventory writes.

Input reviewer checks sources and units. Independently, the verifier processes the same raw three files before seeing the reconciler's results. The reconciler adds movements to book quantity; the verifier walks backwards from physical quantity to the implied snapshot quantity. The leader checks matching source digests, keys, movement IDs and computed results before writing an exception report. The two paths intentionally share parsing and schema constraints, not the accumulation function. Matching software results are not proof of complete movement coverage or physical counts.

Acceptance cases: explained raw discrepancy, unexplained residual, no net variance, offset-equivalent boundary timestamps, duplicate IDs, unit mismatch, missing counterpart, malformed timestamps, incomplete-coverage confirmation, changed source hashes, and altered reconciliation result. Synthetic examples only; no external ERP or account needed.
