# 库存盘点差异复核专家团 1.0.0 手工测试

任务 `AH-20261120-warehouse-stocktake-reconciliation-team`。本页是 WorkSwarm 集成检查步骤，不表示该检查已完成。

1. 确认 WorkSwarm 支持专家团及任务、文件和命令工具，且工作环境有 Python 3.10 或以上。比较原生 ZIP 的 SHA-256 与 `release/1.0.0/artifact.json`，通过「专家 → 我的专家 → 专家团 → 创建 → 上传文件创建」导入 `test-packages/warehouse-stocktake-reconciliation-team-1.0.0-native.zip`，不要上传市场包装 ZIP。安装后选择有权使用的模型。
2. 从同一原生 ZIP 提取 `examples/` 到本机可读路径，建立独立的空输出目录。在新会话授权使用这三份虚构 CSV，并明确账面和实盘都包含各自时点上发生的流水，流水对每个时段均为完整。提供输入和输出的绝对路径，要求真实分派成员并交付三份文件。
3. 查看任务回执：输入检查和独立倒推先于正推；倒推员收到的是原始文件而不是正推结果；正推结束后确实由核验员复查。核对 `review.md`、`exceptions.csv`、`audit.json` 可读且内容一致。
4. 甲账面 10，实盘 13，计入 `in`（+3），不计入恰在账面时点的 `old` 或盘点之后的 `late`，应标记「时点差异已解释」。乙账面 15，计入 `out`（-2），应有 13，实盘为 11，剩余差异 -2，标记「建议复盘」。丙无差异，不列入异常 CSV，但应在审计数据中保留。
5. 用新会话和全新输出目录复测：不声明流水覆盖时应先询问；将实盘文件中甲的单位改为「箱」时，应报告单位不一致且不交付通过结论。
