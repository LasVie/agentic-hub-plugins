# 跨时区例会时间核验专家团

版本 **1.0.0**。把提出的固定本地例会时刻逐周换算，检查每位参会者在当地时间是否能参加完整会议。输出中文报告、CSV 和审查档案，可检查时区切换、跨日、临时不在岗与结束时间越界。

## 安装和开始

在 WorkSwarm 的 **专家管理 → 我的专家 → 专家团 → 创建 → 上传文件创建** 选择原生 ZIP。需要支持原生 AgentGroup 的 WorkSwarm、Python 3.10 及以上、已安装的 IANA 时区数据，以及经你授权的模型和宿主已有任务、文件与命令工具。时间计算只用标准库。导入后检查四位成员及版本。市场包装 ZIP 用于后续交付。

可以复制以下请求，并补入已存在的可写父目录：

> 请用跨时区例会时间核验专家团1.0.0检查随包 examples/clock-change.json。我授权把虚构样例作为明确的原始约定。工作父目录为「你的绝对路径」。请实际分派各成员运行对应脚本。核验员先只读原始案例算出独立基线，再核对规划。各阶段使用新文件及新目录。交付 review.md、meetings.csv、audit.json，说明九点和八点候选的各期结论。

## 输入与结论

- 传入一份 UTF-8 JSON。参见随包例子。结构版本为1。首次日期是本地第一期日期，后续每7天一次。2–8人，4–12周，1–3个候选时刻，15–120分钟。日期支持2000–2099年。
- 给每人提供明确的 IANA 时区、周一至周日全部窗口和本地日期例外。[] 表示无可用窗口；日期例外替换当天的全部正常窗口。24:00仅作终点。跨午夜拆成相邻两日的两个窗口。
- 全部时长按实际 UTC 分钟检查。结束恰好等于窗口终点允许通过。春季缺失时刻及秋季重复时刻分别列报，重复时刻的可选 UTC 值会显示，须由用户提供可确认的替代时刻再核验。
- 目录或资料变更后会失效旧证据。本次读取的实时时区文件以摘要记录，时区规则变更后应重跑。只以用户提供的可用时间为依据；无外部日历、自动排期、邀请或日历修改。

## 交付物与分工

参会时段梳理员对照原始数据，跨时区例会计算员展开各期，独立时刻核验员先从原始输入复算，再比较实际规划。主理人最多协调一轮纠错并检查交接。缺输入、数据不一致或命令失败则说明并停止。

- review.md 包含候选的符合期数和需关注的期次。
- meetings.csv 包含每位参会者的本地起止、UTC、冲突分钟数及第一次冲突。
- audit.json 记录逐期结果、输入摘要、时区指纹与四份真实交接文件的摘要。

复算一致只说明当前输入边界内的结论可重复。个别时段仍可能有冲突或时钟歧义，由使用者决定如何安排。
