# 采购报价比选复核专家团

版本 **1.0.1**。这是原生 `agent_group`，包含比选主理人、技术符合性评估员、商务成本分析员和独立证据复核员。

用途：按用户给定的需求、评分规则和本地报价，分别进行技术与商务初评，再从原文独立复核，交付有证据、可复算、保留分歧的中文比选档案。

## 安装与使用

1. 在 WorkSwarm 打开 **专家管理 → 我的专家 → 专家团 → 创建 → 上传文件创建**，上传本版本原生测试 ZIP。导入后确认它出现在专家团列表，且有 `leader`、`technical`、`commercial`、`verifier` 四个成员。
2. 新建团队会话并选择“采购报价比选复核专家团”。安装成功不能替代实际协作测试。
3. 提供案例 JSON 的绝对路径、原文目录和允许写入的新工作目录。使用交付的合成案例先测试；没有真实授权时不读取业务文件。
4. 要求技术与商务成员分别完成初评，复核员先独立检查原始输入，再比较初稿；在团队任务和消息中核对真实参与。
5. 打开最终生成的 HTML，交叉核对原文行、符合性、总成本、比较结果和待澄清事项。CSV、JSON 和 Markdown 是同一轮计算的辅助记录。

中文请求示例：

> 请使用采购报价比选复核专家团 v1.0.1 审阅我指定的本地案例。我授权读取案例 JSON 和其中列出的原文，并仅在我指定的新目录保存成员初稿和结果。请先返回实际 inspect 版本、摘要和输入问题；再分派 technical 与 commercial，要求 verifier 先独立复算后审阅初稿。成员报告使用 schema_version 2，说明放 notes，未解决问题按 scope 和 category 写入 issues。保留初稿，最多一次有依据的修正。先检查必备条件，明确列出排除原因；资格仍不确定、全局问题或未排除报价的重要分歧尚未解决时停止排名。展示真实文件路径和待澄清项；不覆盖原文件，不联网、不联系供应商或购买。

## 分工和交付

| 成员 | 主要责任 | 交接物 |
|---|---|---|
| `leader` 比选主理人 | 确认输入、固定规则、真实分派、处理分歧并验收 | 中文比选摘要与真实交付路径 |
| `technical` 技术符合性评估员 | 必备要求和技术评分，逐项引用原文 | 独立技术初稿 JSON |
| `commercial` 商务成本分析员 | 币种、数量、次数、一次性/周期成本 | 独立商务初稿 JSON |
| `verifier` 独立证据复核员 | 先独立检查，再核对初稿和解释差异 | 独立复核 JSON 与分歧清单 |

共享 `quote-evaluation` Skill 提供 Python 标准库脚本，通过宿主已有命令工具运行。它核对原文引文、摘要、结构、算术和跨报告一致性，不声称替代语义判断。所有代码均随包提供，不修改宿主，不安装第三方依赖，不增加业务服务。

输出为新目录内的中文 HTML、CSV、JSON 与 Markdown 档案；实际文件名和路径以 `deliver` 的真实返回为准。材料缺失或仍有重要分歧时可交付“待澄清”档案，不能宣称已有最终优胜者。

## 先判资格，再比较合格报价

技术成员和独立复核员对同一必备条件均明确判定 `fail`，且该报价没有必备条件未知、必备状态冲突或资格问题时，才将其列为“已排除”，保留对应要求和原文理由。必备条件未知或有分歧仍会阻断排名，不能因另一条件失败而掩盖。

已确定排除的报价，其非必备评分未知、评分分歧或成本缺失保留为可见警告，不再阻断其余合格报价的比较。全局问题、资格不确定，以及所有未排除报价的问题、评分或成本缺口仍会阻断。所有原文、摘要、报告字段、完整条目和引文先校验；排除报价不享有无效报告或错误引文的例外。

成员报告版本为 `schema_version: 2`：`notes` 是信息说明，`issues` 是带作用范围的未解决问题。已知必备条件失败写在评估条目中，可在 `notes` 解释；不得把真正的问题移到 `notes` 以绕过检查。旧版字符串问题列表不会静默转换，须保留旧稿并另存本版报告。案例 JSON 仍使用 `schema_version: 1`，排名公式保持不变。

## 输入与证据边界

`compliance.csv` 同时列出资格状态及本项阻断问题/非阻断警示；`costs.csv` 保留已排除报价的声明金额并明确资格状态。信息说明、完整处置和排名详见同轮 HTML、Markdown 与 JSON，不能从低金额推断报价合格。

- 2–4 份报价，最多 10 项要求；输入是 UTF-8 JSON 与案例目录内明确列出的本地文本来源。
- 明确币种、期间、金额、数量、次数和规则。本版不做 PDF/OCR、汇率查询、税费推断、实时价格搜索或供应商背景调查。
- 本版只支持案例明确选用的 `weighted-min-cost-v1`：技术项按量表加权归一化；成本项取最低合格成本/本报价成本，再按两类权重合成。所有合格总成本须大于零，同分并列。其他评分方法不支持，完整公式见输入格式；不能仅给最高分而缺少可执行量表。
- 报告绑定实际 `case_sha256`；原文或规则变化后必须重新检查。来源行号从 1 开始，引用必须逐字出现且属于对应报价。
- 引文存在不等于语义上支持判断。结构金额与原文矛盾时必须澄清，不能靠一致的三个报告掩盖。
- 原始材料只读，新输出路径已经存在时拒绝覆盖。

完整字段与成员报告契约见 [输入格式](skills/quote-evaluation/references/input-format.md)。共享 Skill 中的命令使用当前安装包脚本的真实位置，不依赖开发者机器路径。

## 限制与验收

角色分工不是安全隔离或真正盲审；报告的角色字段也不是成员参与证明。实际参与需查看宿主的成员任务、消息、工具调用和输出。一次修正后仍有阻断事项时保留问题，停止排名；已排除报价的非必备评价警告继续展示，不冒充已解决。

单个专家也能进行报价比较。本团期望通过独立初评与复核减少遗漏；不能在同模型、同工具、相同总 token 预算的实际比较完成前宣称质量或成本更优。脚本/安装检查、无付费的确定性模型测试、真实模型协作和用户人工测试分别记录，互不替代。

本包不自动联系供应商、采购、签约或发布，不提供法律、财务审计或正式采购合规认证。所有采购决定由用户负责。本包未包含任何业务账号、密钥或真实报价。
