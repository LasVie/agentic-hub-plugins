# 每周工时记录复核专家团

v1.0.0 · 复核一个人的每周工时记录，按源行定位重复、时间重叠、缺失打卡和需要核实的预计日期。输出中文 HTML 清单、逐行 JSON 与文件摘要。适合每周提交前核对项目工时、计时与手工录入，或检查包含跨午夜的班次。

## 安装与使用

在支持原生 AgentGroup 的 WorkSwarm 中打开「我的专家 → 专家团 → 创建 → 上传文件创建」，选原生 ZIP。宿主需有已授权的模型、可读取输入与写入指定目录的文件及终端权限，以及 Python 3.10 或更新版本。可另将原生 ZIP 解压到名为 `weekly-timesheet-review-team` 的目录进行宿主校验。

提供以下资料及一个可写的输出父目录：

- 周设置 JSON，例如 `{"week_start":"2026-11-16","utc_offset":"+08:00","expected_days":["2026-11-16"]}`。检查范围为从起始日 00:00 开始的七天。预计日期可省略。时间必须已经统一为明确的固定 UTC 偏移，遇到夏令时或跨时区更换时先统一换算。
- 一个 UTF-8 CSV，表头 `project,start,end`。日期时间使用 `YYYY-MM-DD HH:MM`。每行最多 24 小时，过午夜时填写正确的结束日期。可以同时加上 `break_start,break_end` 两列，填写落在该行时间段内的一个休息时段。无休息时两格留空。每次最多 300 条记录。可以直接在会话粘贴完整 CSV 文本，确认准确保存后由团队执行。

```csv
project,start,end,break_start,break_end
周报,2026-11-16 09:00,2026-11-16 11:00,2026-11-16 10:00,2026-11-16 10:15
值班,2026-11-16 22:00,2026-11-17 02:00,,
```

以上记录计入 345 分钟，其中 225 分钟落在 11 月 16 日，120 分钟落在 11 月 17 日。没有输入的分钟不会被推定。没有可汇总工时的预计日期需要核实，不能据此判定缺勤。

主理人先派独立复核员完成初核，再派分析员计算，随后由同一复核员逐行核对，最后交付 `checklist.html`。重叠只看扣除明确休息后的工作区间，相邻时间不重叠；同一重复组或重叠涉及的有效行全部暂缓计入。计入时长只包含在审查周内的分钟。源记录更正、薪资计算、提交与批准由使用者或其系统处理。
