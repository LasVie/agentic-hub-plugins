# 日常洗衣分批复核专家团

把一篮衣物变成一页中文清单。输出各批的衣物、件数、可用机洗程序、洗后干燥去向及待确认项。适合家庭混合衣篮、运动衣和校服、共享洗衣房。首次只需确认手边用到的衣物组和机器程序；以后可以复用原表并调整件数，有新衣再增加组别。

在 WorkSwarm 的「专家管理 → 我的专家 → 专家团」安装并打开原生包。需要 WorkSwarm 原生团队任务、已授权的模型、Python 3.10+ 及本地文件和命令权限。验算无需联网或第三方库。

## 给团队的资料

可粘贴简短中文原话，让主理人将确认的约束写成冻结案例。例：「浅色上衣 5 件，已确认机洗最高 40°C 标准、允许低温烘干；深色上衣 3 件，最高 30°C 轻柔、悬挂晾干；新红衣 1 件，标签未读清。机器确认有标准 40°C、轻柔 30°C。」还要明确各组是否须分洗。只有所有护理条件相同的衣物才合为一组。

也可直接给本地 UTF-8 JSON。顶层为 `schema: 1`、`title`、`profiles`、`programs`、`basket`。组别和程序编号使用小写英文字母开头，可含数字、短横线和下划线。每次最多 40 个组、80 件。

- `profiles` 是以编号为键的对象。每组填 `name`、标签的简短原话或缺失说明 `label`、`color`（`light/dark/bright` 或 `null`）、`separate`（`true/false/null`）、`wash` 和 `dry`。
- `wash` 包含 `method`（`machine/hand/no_machine/unknown`）、`max_celsius`（整数或 `null`）和 `max_action`（`normal/gentle/very_gentle` 或 `null`）。非机洗组的两项上限均填 `null`。诸如「冷水」而未确认对应温度的描述不换算为具体温度。
- `dry` 支持 `line/flat/line_shade/flat_shade/tumble_low/tumble_normal/unknown`。按用户明确的干燥动作录入；无法归入支持动作时采用 `unknown`，在洗后处理前另核对。
- `programs` 按使用优先顺序给列表，每条填 `id`、面板程序名 `name`、实际 `celsius`、动作强度 `action` 和可选件数限制 `max_items`（不明填 `null`）。最多 12 项。件数只是用户给定的排程约束，不能替代机型的额定重量或装载规则。
- `basket` 用组别编号映射正整数件数。保留 `profiles` 和 `programs` 可下次重复使用。当前提供文件复用，不自动跟踪衣物或连接机器。

## 核对与交付

独立复核员先冻结可用程序范围，规划员随后分批，复核员再核对具体分配。报告 `checklist.html` 可直接离线打开，`evaluation.json` 保留复核结果，`artifact.json` 记录原案、交接和清单的 SHA-256。遇到候选冲突则显示中文原因，暂不输出可执行分批。只要可用洗涤批次通过核查，就会同时列出单独的手洗、未确认护理或干燥待处理项。

本团专注于家用分批与洗后去向。特殊污渍、消毒、漂白、溶剂、专业处理和机器自动操作超出范围。实际物品、配件和装载仍按标签与机器说明核对。
