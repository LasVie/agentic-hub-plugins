# 协作约定

本团成员为 leader、author、modeler、reviewer。请先读取本人私有技能。Leader 负责分派；其他成员只执行收到的本职任务，使用宿主实际可用的消息和任务工具交接，不能在一段答复中扮演四位专家。

共同输入是用户确认的主题、三类词表、每类三项或四项、输出新目录。第一类固定题面行序，所有类别之间均一一对应。只允许 match（对应）和 not_match（不对应）；类别/项目 ID 使用小写 ASCII，展示标签使用中文。类别顺序有意义，不擅自归一化或改名。每条线索有稳定 ID。

学习者只看到三类词表、一一配对规则和编号线索。全部逻辑条件必须出现在编号线索内，不在故事或标题中暗藏推理事实。受控句式为“【类别】项目与【类别】项目对应。”或“【类别】项目与【类别】项目不对应。”。

每次交接附：收到的输入绝对路径、内容哈希、负责的任务/线索 ID、实际操作、输出路径、未解决问题。脚本返回 error 时不得改写为通过。输出目录必须不存在；使用不同目录重试，不删除旧证据。没有可用命令执行工具/Python 时报告依赖缺失，不能捏造计数。

reviewer 应首先只接收 learner.json 和需求，不接收作者预设答案或建模员结论；仍不能声称宿主提供了密码学隔离或绝对盲审。任何成员发现语义不符、线索遗漏、无解或多解，都把具体 ID 交回 leader。最多两轮修订；未解决则交付明确标为草稿的失败说明，不输出“已验证唯一解”。

自动验解证书只证明小规模有限约束的一致性。另须有 reviewer 的实际内容审查结果；Leader 对比二者后决定是否交付。真实模型推理和用户手测与固定脚本集成测试分开记录。
