# 逻辑网格谜题编制与验解专家团

版本：1.0.0。把用户确认的主题和三类词表编成原创中文配对谜题，经过完整解数计算与独立复核，交付可打印的题面、单独答案和审计记录。

## 成员与真实协作

| 成员 | 负责的工作 | 交接物 |
| --- | --- | --- |
| leader：统筹与交付负责人 | 确认需求、分派、处理分歧、核查实际文件 | 最终题面和交付说明 |
| author：原创谜题编制员 | 原创词表、预设配对和编号线索 | model.json、单独的预设答案说明 |
| modeler：约束建模与计数员 | 完整枚举全部合法配对 | learner.json、model-report.json |
| reviewer：独立验解与语义复核员 | 从学习者中文原文重建约束，独立验解并审阅内容 | review.json、内容复核意见 |

成员通过宿主的原生委派、消息与文件工具合作；脚本不会替 Leader 调度代理。仅声明四名成员、导入成功或数学脚本通过均不证明真实协作。Leader 必须等候各成员实际完成后交付。审阅员先接收题面而非预设答案；宿主上下文能否绝对隔离并不由本包保证。

## 安装与前提

在兼容 WorkSwarm 中进入“专家管理 → 我的专家 → 专家团 → 创建 → 上传文件创建”，选择 **native 原生测试 ZIP**。此处不要上传带 plugin.yaml 的市场包装 ZIP。安装完成后选择本团使用。

需要支持 AgentGroup、成员原生委派、文件读写及命令执行的宿主；Python 3.10 或以上（仅标准库）；用户自行配置并授权的可用模型。包不包含 API 密钥、模型、连接器或外部依赖安装器，不需要付费服务。会话模型自身的费用和数据流由宿主配置决定。工具缺失时应明确报告，不能伪造结果。

## 范围

- 三个类别，每类三个或四个不同项目，类别间一一对应；第一类固定行序。
- 只支持“对应”和“不对应”，每条线索有稳定编号。最多 32 条线索。
- 使用精确受控句式：“【人物】小林与【饮品】茶对应。”或“【人物】小林与【饮品】茶不对应。”。故事/标题不额外暗藏条件。
- 3 项情况枚举 36 个候选配对；4 项情况枚举 576 个。无解、多解和复核分歧均不输出合格题包；最多两轮修订后仍不通过则停止在草稿。

暂不支持顺序、相邻、数值比较、析取、任意自然语言关系或更大网格。精确计数证明有限模型的解数，不证明题目难度、线索最少、仅靠直观演绎可解，或模型理解绝对正确。受控句式解析不能代替独立成员的语义和受众适宜性审阅。

## 中文用例

```text
请编一份校园主题逻辑网格谜题，面向初次接触配对谜题的读者。
人物：小林、小陈、小王；饮品：茶、果汁、牛奶；活动：阅读、绘画、跑步。
仅用对应/不对应线索。请真实委派 author、modeler、reviewer，先让复核员只看 learner.json。
把题面和答案分别保存到我指定的全新绝对目录：<填写不存在的目录>。
请报告每名成员实际做了什么，解数是多少，哪些内容仍需人工判断。
```

也可要求“按随包 examples/campus-model.json 运行一次验解示例”；示例是原创测试数据，固定脚本测试不等于模型独立编题通过。成员技能给出脚本的准确调用方式；不得假定脚本所在目录就是当前工作目录。

## 文件交付与保护

`puzzle.html` 是学习者题面和空白网格，不含答案；`answer.md` 单独保存答案与线索依据；`audit.json` 记录有限模型、独立复算和文件哈希。不要把答案文件和审计文件发给正在解题的学习者。独立复核使用 `learner.json`，原始模型和所有旧结果应保留。

所有写入要求全新输出目录，遇到已有目录、无效输入、陈旧报告、不可支持关系或工具故障时明确失败，禁止覆盖原文件。HTML 对标签做转义；不执行用户输入的表达式或代码。输出的计数证据不证明另一个成员已参与；另看实际会话轨迹和内容复核意见。
