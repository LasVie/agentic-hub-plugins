# 网购扣款与退款核对专家团

每周用订单、支付记录和退款通知核对实际入账，找出仍需跟进的交易。四个角色分别负责范围与交付、原始记录梳理、扣款退款匹配和独立核验。使用 WorkSwarm 专家团原生机制和 Python 3.10 以上标准库；通过现有文件和命令工具运行。无需登录网购或支付账户。

## 输入

可粘贴记录，或提供一个目录下三份 UTF-8 CSV。粘贴内容须先整理到以下三表并核对来源。请确认核对截止日，提供足以覆盖订单和退款的账单摘录，删去姓名和完整账户号码。

| 文件 | 表头 |
| --- | --- |
| orders.csv | 订单号,下单日期,商户,币种,实付应扣 |
| payments.csv | 流水号,记录日期,商户,币种,方向,状态,金额,订单号,退款单号 |
| refunds.csv | 退款单号,确认日期,订单号,币种,确认金额 |

日期写 YYYY-MM-DD；币种用三个大写字母；金额是正数，支持最多三位小数。订单实付应扣填券后含应付运费金额。每表标识唯一，跨账户的流水号可加来源前缀。方向仅填“扣款”或“退款”，状态填“已入账”或“待入账”。流水的订单号和退款单号可以空白；无退款通知时保留退款表头。每表最多 100 行数据、512 KB。相同商户名用于比较，已知别名请明确确认并保留原始文本。样例为虚构记录，不代表支付渠道规则。

明确订单号优先，所涉商户、币种和日期仍须相符。没有订单号时，仅在下单当天到第七天内，币种、商户、金额一致且双方都没有其他候选或已有明确扣款时自动关联。退款按明确退款单号关联到账，可多条合计。缺引用时保留未分配。金额不换汇；差额只针对用户提供的范围。

## 试用

将中文原生 ZIP 导入 WorkSwarm，进入专家团级对话并选择你获授权使用的模型。首次用例指定随包 examples/weekly 为已授权资料、截至日 2026-11-20，并指定一个工作父目录。原生 ZIP 手工解压时，包目录以 manifest.json 所在目录为准。每阶段在工作父目录中选择独立且尚不存在的子目录。

先分派资料梳理和仅凭原始资料的独立基线，随后匹配、核验、交付。预期 A100 的两笔扣款 50 和 70 合计 120，待入账授权单列；R01 确认 30，已入账 12，差额 18；P005 对应两张同额订单，保留未分配；P006 唯一匹配 A103。核验通过仅表示核对结论与证据一致。

交付 review.md、reconciliation.csv、audit.json，包括待跟进原因、原始行号和逐币种金额。不会连接账户、办理退款或发送消息。
