# 家庭日用品补货核验专家团

用于家庭或合住者每周采购前核对库存，也可以在到货时间变化之后重新核对。在 WorkSwarm 的专家团上传本组原生 ZIP。此组使用本地文件和命令工具，脚本需要 Python 3.10 或以上。

## 开始使用

把盘点日期、下一次常规采购日期、可用数量和估计日耗交给主理人。能提供时，补充已确认的到货日、包装量、规格和存放上限。也可以直接把本地原始 JSON 的路径交给主理人，并指定一个允许写入结果的父目录。只使用你提供的标签、数量和规格，不查询商家或代为购买。

可直接粘贴这类备注：“11 月 23 日盘点，11 月 30 日下次采购。卷纸有 2 卷，约每天用 1 卷。11 月 27 日确认到货 6 卷。可以买 2 卷装或 6 卷装，最多放 6 卷。”

### 输入文件

参照 [虚构周采购案例](examples/weekly-restock.json)。同一用品的数量统一使用 `unit`，例如“卷”。同品名和所需规格只登记一项，分批的数量可填在同一项的 `stock` 或 `arrivals` 中。不填写估计值来替代未知的数量。

| 字段 | 填写方式 |
| --- | --- |
| `as_of`、`next_shop` | 填盘点日及下次常规采购日，使用 YYYY-MM-DD，间隔 1 至 90 天 |
| `items` | 最多 100 种用品，每项写 `name` 和 `unit` |
| `daily_use`、`stock` | 日耗可填到千分之一，未知填 `null`。记录可用盘点，数量用 `qty`，未知填 `null`。已确认无库存填空列表 |
| `arrivals` | 可选。按 `qty`、`date`、`status` 登记，已确认填 `confirmed`，待定填 `pending` |
| `variant` | 仅对需要核对规格的用品填写所需规格。各条存量、到货、包装也要填自己经用户确认的规格，按完全一致计入 |
| `packs`、`capacity` | 可选。每个包装选项填 `qty`，需要时附 `variant`。存放上限用同一单位，表示这一种用品可容纳的总量 |

盘点日是起点。每天先计入已确认、已知量、已知日期、适配的当天到货，再扣除预计日耗。下次采购当天不在覆盖期内。建议一次购入能覆盖全期最大缺口的最少数量，选同一规格的整包，且覆盖期内每日存量均须符合提供的上限。同量时选较少包数。未给包装量时仍可看到缺口和日期，包装数量留待确认。

## 核对和交付

库存与到货核对员先登记可用量、到货与包装。独立核验员只看原始盘点并封存基线。主理人出补货方案后，由同一核验员对照原文和基线核对，再交付：

- `shopping-list.md`，可立即用于采购前准备的中文清单。
- `restock.csv`，逐项缺口、建议包数、存放约束及备注。
- `audit.json`，输入和核验回执摘要，以及交付文件的 SHA-256。

脚本的阶段参数见 [补货证据技能](skills/restock-evidence/SKILL.md)。所有阶段使用新的输出目录。缺少有效核验回执时不生成正式清单。
