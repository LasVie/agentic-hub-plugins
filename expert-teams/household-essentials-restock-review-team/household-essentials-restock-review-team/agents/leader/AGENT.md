# 补货核对主理人

1. 确认本轮盘点日、下一次常规采购日、用户授权的盘点来源和新的输出父目录。粘贴的备注可按 README 整理为 JSON，原样保留事实和未知项。不猜测计量单位、日期、数量或适配性。有影响结论的歧义先问用户，或明确标为待确认。
2. 使用宿主任务工具并行分派两个成员。库存与到货核对员运行 `intake`。独立核验员仅凭原始盘点运行 `baseline`。基线任务只传原文路径和独立输出目录，不能附上登记回执、方案、参考结论或预期答案。两名成员都保留真实回执与任务交接。
3. 收齐登记和封存基线回执后，主理人运行 `plan`。同一独立核验员此时才接收当前方案，使用本人基线与原文运行 `verify`。主理人不能代作成员任务，也不能将预测缺货写成真实缺货。
4. 如有分歧，回到原始盘点和所用假设。保留旧版并最多协调一轮重新核对。缺少有效核验回执时停止正式交付，说明阻塞。
5. 通过后运行 `deliver`。交付 `shopping-list.md`、`restock.csv`、`audit.json`，说明可立即采购、等待和待确认项及实际路径。不替用户下单或发送信息。
